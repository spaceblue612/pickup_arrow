# 레벨 난이도 적용 가이드

## 현재 적용 구조

실제 게임 스테이지는 `scripts/stage_catalog.gd`의 `STAGE_CONFIGS`에서 설정합니다.
현재 게임 보드는 모든 스테이지가 `GRID_SIZE = Vector2i(9, 9)`를 공유합니다.

난이도 설정은 두 층으로 나뉩니다.

1. 형상·밀도 설정으로 생성 후보의 기본 성격을 정합니다.
2. 의존 목표 설정으로 후보를 측정하고 목표 범위에 든 첫 보드만 채택합니다.

## 형상·밀도 설정

```gdscript
"primary_arrow_count": 5,
"min_length": 5,
"max_length": 14,
"target_empty_ratio": 0.40,
"filler_max_length": 3,
```

- `primary_arrow_count`: 기본 화살 수입니다. 많을수록 상호작용 가능성이 증가합니다.
- `min_length`, `max_length`: 기본 화살 길이 범위입니다.
- `target_empty_ratio`: 전체 보드의 빈칸 비율입니다. 낮을수록 조밀합니다.
- `filler_max_length`: 목표 점유율을 맞추는 보충 화살의 최대 길이입니다.
- `seed`: 첫 생성 후보의 기준 seed입니다.

밀도와 길이는 의존 난이도에 영향을 주지만 원하는 난이도를 보장하지는 않습니다.
최종 보장에는 아래 의존 목표가 필요합니다.

## 의존 목표 설정

```gdscript
"dependency_target": {
    "min_dependency_depth": 4,
    "max_dependency_depth": 8,
    "min_initial_extractable_ratio": 0.00,
    "max_initial_extractable_ratio": 0.40,
    "min_forced_state_ratio": 0.20,
    "max_forced_state_ratio": 1.00,
},
"max_candidate_attempts": 64,
```

- `dependency_depth`: 선행 제거 연쇄의 최대 길이입니다. 높을수록 긴 연쇄를 요구합니다.
- `initial_extractable_ratio`: 시작 시 바로 제거 가능한 화살 비율입니다. 낮을수록 초반 선택이 제한됩니다.
- `forced_state_ratio`: 해결 과정에서 선택지가 하나인 상태의 비율입니다. 높을수록 진행이 선형적입니다.
- `average_choice_count`: 채택 조건은 아니며 결과 확인용입니다.
- `max_candidate_attempts`: 목표 후보를 찾기 위해 검사할 최대 개수입니다.

`forced_state_ratio`가 높다고 항상 체감 난이도가 높은 것은 아닙니다.
선택지가 줄어 퍼즐이 단순해질 수도 있으므로 `dependency_depth`, `initial_extractable_ratio`,
`average_choice_count`와 함께 판단해야 합니다.

## 권장 적용 순서

1. `primary_arrow_count`, 길이 범위, 빈칸 비율로 원하는 보드 밀도를 먼저 정합니다.
2. 여러 seed의 `dependency_analysis`를 표본 측정합니다.
3. 쉬운 레벨은 낮은 깊이·높은 시작 가능 비율을, 어려운 레벨은 높은 깊이·낮은 시작 가능 비율을 목표로 둡니다.
4. 단일 값 대신 허용 범위를 사용합니다. 범위가 좁으면 생성 재시도 비용이 빠르게 증가합니다.
5. `dependency_targeting_metrics["attempt_count"]`를 확인해 평소 10회 안쪽에서 선택되는지 점검합니다.
6. 전체 테스트를 실행해 해결 가능성과 기존 게임 흐름을 확인합니다.

## 결과 확인

```gdscript
var stage := StageCatalog.get_stage("STAGE-003")
print(stage["generation_profile"])
print(stage["dependency_target"])
print(stage["dependency_analysis"])
print(stage["dependency_targeting_metrics"])
```

주요 결과:

- `selected_seed`: 실제 채택된 후보 seed
- `attempt_count`: 채택까지 검사한 후보 수
- `dependency_analysis`: 실제 의존 지표
- `has_complete_solution`: 완전 해결 가능 여부

## 보드 크기 변경 시 주의

`DependencyTargeting`, `ArrowPlacement`, `DependencyAnalyzer`는 임의의 `grid_size`를 받을 수 있습니다.
다만 현재 런타임 그리기와 스테이지 검증은 `StageCatalog.GRID_SIZE` 하나를 공유합니다.

전체 게임 보드를 키우려면 다음을 함께 확인해야 합니다.

1. `scripts/stage_catalog.gd`의 `GRID_SIZE`와 길이·밀도 설정
2. 각 스테이지의 의존 목표 범위 재보정
3. `scripts/main.gd`의 셀 크기와 터치 영역
4. 모든 회귀 테스트와 실제 모바일 화면 가독성

스테이지마다 서로 다른 보드 크기를 사용하려면 `main.gd`가
`StageCatalog.GRID_SIZE` 대신 현재 `stage_definition["grid_size"]`를 사용하도록 별도 변경해야 합니다.
