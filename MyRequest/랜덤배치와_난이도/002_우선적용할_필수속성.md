# 002 — 우선 적용할 필수 속성

작성일: 2026-10-29  
참조: [001 기초 조사](001_공개로직과_속성_기초조사.md)  
상태: 첫 구현 범위를 좁히기 위한 제안. 신규 속성과 도구 연결은 아직 구현하지 않았습니다.

## 이번 정리에서 달라진 점

001은 측정 가능한 후보를 넓게 조사했습니다. 이번에는 **입력을 바꾸면 생성할 목표가 명확하고, 생성 후 툴에서 결과를 확인할 수 있는 항목**만 먼저 추렸습니다. 세부 통계는 첫 화면의 입력으로 늘리지 않고, 배치 원칙은 [003](003_배치규칙과_적용로직.md)에서 따로 관리합니다.

## 1. 작업 대상은 현재 보드·영역을 사용합니다

기존 보드 크기와 금지 칸을 사용하고 생성 대상은 전체 보드 또는 선택 영역으로 정합니다. 기존 화살은 보존하고 빈 공간에 추가하는 작업을 기본으로 제안합니다. 초기화를 원하는 경우에는 별도 동작으로 구분합니다.

보드 크기와 생성 범위는 배치의 바탕입니다. 아래 여섯 속성이 사용자가 결과를 바꾸기 위해 조절할 핵심 입력입니다.

## 2. 채우기 설정 — 세 가지

| 속성 | 사용자가 정할 것 | 실제 배치에 적용할 것 | 툴에서 확인할 것 |
|---|---|---|---|
| **빈칸 허용도** | 생성 후 남길 빈칸 비율 | 금지 칸을 제외한 대상 공간을 목표 점유까지 채움 | 목표·실제 빈칸 %, 추가 점유 칸 수 |
| **화살 크기 구성** | 짧음·중간·김의 길이 범위와 개수 비중 | 부족한 크기 종류를 우선 생성 | 종류별 화살 개수·비중과 평균 길이 |
| **꺾인 화살 비중** | 한 번 이상 꺾이는 화살의 개수 비중 | 직선/꺾임 목표에 맞춰 몸체 생성 | 목표·실제 꺾인 화살 %, 보드 강조 |

크기 구성은 기본값을 제공하고 길이 범위는 필요할 때 펼쳐 수정하게 합니다. 범위는 서로 겹치지 않게 정하며 제작 규칙대로 최소 2칸을 사용합니다. '짧음'처럼 이름만 두고 실제 길이는 바뀌는 방식은 피합니다.

크기와 꺾임의 비중은 **이번에 추가한 화살의 개수 기준**입니다. 기존 수동 화살 때문에 추가 결과의 구성이 바뀌지 않도록 하되 전체 맵 비중도 함께 확인할 수 있게 합니다. 짧고 꺾인 화살처럼 두 속성에 동시에 속할 수 있으므로 두 비중을 합산하지 않습니다.

빈칸 비율은 생성 범위의 배치 가능 칸을 분모로 삼고 **기존 화살의 점유까지 포함한 최종 상태**에서 계산합니다. 예를 들어 100칸 중 기존 30칸 점유, 빈칸 목표 20%라면 약 50칸을 추가합니다.

초기에는 전체 화살 수를 별도의 필수 입력으로 고정하지 않습니다. 점유 목표와 길이 구성으로부터 결과 개수가 결정되게 해 조건 충돌을 줄입니다. 한 개씩 화살을 더할 때마다 목표 비중은 조금씩 어긋날 수 있으므로 목표와 실제를 함께 표시합니다.

## 3. 풀이 관계 설정 — 세 가지

| 속성 | 사용자가 정할 것 | 실제 배치에 적용할 것 | 툴에서 확인할 것 |
|---|---|---|---|
| **시작 선택지 수** | 시작 시 바로 뺄 수 있는 화살 수의 범위 | 생성한 몸체·방향으로 출발점 수를 조절 | 실제 개수, 해당 화살 강조 |
| **연결 길이** | 선행 제거가 차례로 이어지는 화살 수의 목표 범위 | A를 빼야 B, B를 빼야 C가 열리는 연결 생성 | 최장 연결과 연결된 화살의 보드 강조 |
| **연결 참여 비중** | 목표 최소 길이 이상의 연결에 포함될 화살의 비율 | 긴 연결 하나만 만들고 끝내지 않고 여러 곳에 배분 | 참여 화살 고유 개수·비중, 보드 강조 |

연결 길이는 **화살 개수**로 표기합니다. A → B → C는 3개 연결입니다. 기존 분석기의 깊이 계산과 표기 단위를 맞춰 혼동을 막습니다.

연결 참여 비중은 '목표 최소 길이 이상의 선행 경로에 들어가는 고유 화살 수 / 전체 화살 수'입니다. 한 화살이 여러 경로에 속해도 한 번만 셉니다. 시작 선택지와 두 연결 속성은 **전체 맵의 최종 상태**를 기준으로 확인합니다. 선택 영역 생성 시에도 영역 밖의 방해 관계를 포함합니다.

참여 비중을 두는 이유는 최장 연결만 5개이고 나머지 대부분은 바로 빠지는 결과를 구분하기 위해서입니다. 연결 길이만 늘려도 맵 전반이 원하는 방식으로 바뀌지는 않습니다.

이 세 값은 풀이 구조를 통제합니다. 값이 높거나 낮다는 이유만으로 체감 난이도를 확정하지 않습니다. 특히 연결을 알아낸 후 연속으로 빼는 부분은 쉽게 느껴질 수도 있습니다.

## 4. 입력을 늘리지 않고 먼저 확인할 결과

- **클리어 가능 여부:** 공용 게임 규칙으로 전체 화살 제거가 가능한지 확인합니다.
- **선택지 변화:** 한 화살씩 빼면서 현재 제거 가능한 개수가 어떻게 바뀌는지 보여줍니다. 분석에서 사용한 제거 순서를 표시합니다.
- **한 번에 새로 열리는 수:** 선택한 화살 제거 전후에 무엇이 새로 열리는지 강조합니다.
- **목표와 실제 차이:** 채우기 3개·풀이 관계 3개 각각을 표시합니다. 일부 미달인 결과를 전체 성공으로 표시하지 않습니다.

이 결과를 보고 실제 필요성이 확인되면 압박 빈도·다중 차단 비율·관문 개방량을 다음 입력으로 승격합니다. 지금은 별도의 생성 목표로 모두 추가하지 않습니다.

## 5. 조작 예시

다음은 동작 설명용 예시이며 검증된 난이도 기본값은 아닙니다.

- 선택 영역을 생성 대상으로 하고 빈칸은 약 15% 남깁니다.
- 화살 크기는 짧음 50%·중간 30%·김 20%, 꺾인 화살은 약 40%로 정합니다.
- 전체 맵에서 처음 뺄 수 있는 화살은 3~5개, 연결은 3~5개 길이, 연결 참여는 약 60%를 목표로 합니다.
- 생성 후 목표와 실제, 출발점, 연결 참여 화살을 확인하고 풀이를 재생합니다.

임의 모양의 작은 영역이나 기존 배치에 따라 이 조건을 동시에 만족할 수 없을 수 있습니다. 도구는 기존 화살을 보존하고 미달한 항목을 보여줘야 합니다. 목표 비율의 허용 오차는 자동 반올림과 생성 한계를 확인한 뒤 정하며, 미리 체감 난이도 공식으로 고정하지 않습니다.

## 6. 기존 기능을 가져오는 범위

길이·목표 점유·몸체 꺾임 생성과 현재 제거 가능 수·최장 연결 분석은 기존 코드를 활용합니다. 크기 구성의 부족분 보충, 연결 참여 비중 측정, 기존 배치를 보존하는 부분 생성, 도구의 생성 요청·결과 화면은 추가 구현 대상입니다.

처음에는 기존 후보 생성과 비교를 활용하되, [003의 규칙](003_배치규칙과_적용로직.md)으로 원하는 배치를 유도합니다. 수치만 검사하며 완전 무작위 후보를 계속 버리는 방식에 의존하면 원하는 조합을 찾는 시간이 길어질 수 있습니다.
