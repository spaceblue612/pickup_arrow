# 004 — 배치와 난이도의 효과 검증 기준

작성일: 2026-10-29  
참조: [002 필수 속성](002_우선적용할_필수속성.md), [003 배치 규칙](003_배치규칙과_적용로직.md)  
상태: 툴에 연결할 실용 검증 기준의 제안. 검증 기능 구현·수치 보정은 아직 수행하지 않았습니다.

## 이번 정리에서 보강한 점

002의 입력 여섯 개만으로 배치 품질이나 체감 난이도가 보증되지는 않습니다. 이번에는 각 입력과 배치 규칙에 대해 **무엇을 검사하고, 어떤 근거를 보드에서 보여주며, 효과를 어떻게 비교할지**를 정합니다. 공간의 균일한 채움은 별도의 기본 품질 기준으로 추가합니다. 이전 문서의 입력 여섯 개와 구별해 기록합니다.

## 1. 결과 판정을 세 단계로 나눕니다

| 판정 | 의미 | 처리 |
|---|---|---|
| 사용 가능 | 기존 화살 보존, 몸체 규칙·경계·금지 칸·겹침 검사와 전체 클리어 검사 통과 | 실패하면 결과를 정상 후보로 적용하지 않음 |
| 배치 목표 달성 | 빈칸·공간 분포·화살 구성·선행 관계가 지정한 범위 안에 있음 | 항목별 목표·실제·차이를 보여줌 |
| 체감 효과 확인 | 직접 플레이했을 때 탐색·판단 부담이 의도한 방향으로 달라짐 | 비교 플레이로 확인. 앞의 두 판정만으로 완료 표시하지 않음 |

예를 들어 클리어 가능하고 빈칸 20%도 맞았지만 왼쪽만 빽빽하면 '사용 가능 / 분포 미달'입니다. 모든 수치 목표를 맞춰도 쉬워 보이면 '구조 목표 달성 / 체감 효과 미확인'입니다.

## 2. 공간을 고르게 채웠는지 검사합니다

### 2.1 전체 빈칸 비율

전체 보드 또는 생성 영역에서 금지 칸을 제외한 칸을 분모로 사용합니다. 최종 점유에는 기존 화살과 신규 화살을 모두 포함합니다. 목표값과 실제값, 비율 차이와 칸 수 차이를 함께 표시합니다.

이 검사는 전체 수량만 확인합니다. 아래 분포 검사를 별도로 통과해야 고르게 채웠다고 판단합니다.

### 2.2 구역별 점유 차이 — 첫 필수 분포 검사

생성 대상의 바깥 사각 범위를 기본 3×3으로 나누고, 각 구역에 속한 실제 생성 대상 칸 중 금지 칸을 제외한 칸으로 점유율을 계산합니다. 사용자가 만든 관리 영역을 다시 정의하는 동작이 아니라 분석용 임시 분할입니다.

- 전체 점유율과 각 구역 점유율을 비교합니다.
- 가장 덜 채워진 구역이 전체보다 얼마나 낮은지, 가장 많이 채워진 구역과 얼마나 차이 나는지 확인합니다.
- 검사 구역을 보드에 표시하고 점유율 숫자·색으로 빈 부분을 강조합니다.
- 대상 칸이 없는 구역은 제외합니다. 칸이 너무 적은 구역은 작은 표본으로 표시하고 최종 분포 판정에서 제외합니다. 처음에는 10칸 미만을 작은 표본으로 제안하며 실제 맵 크기로 조정합니다.
- 모든 구역이 작은 표본이면 분포를 '균일함'으로 통과시키지 않고 작은 범위용 검사 필요로 표시합니다. 첫 구현에서는 전체 값과 보드 미리보기로 판단합니다.

초기 시험 기준의 예시는 **각 평가 구역이 전체 점유율보다 15%p 이상 낮지 않고, 구역 최대·최소 차이가 20%p를 넘지 않는 것**입니다. 이는 구현을 시험할 시작값이며 검증된 표준이 아닙니다. 문서의 예시를 숨은 고정 상수로 적용하지 않고 도구의 검사 기준에 표시합니다.

예를 들어 전체 점유율이 80%인데 왼쪽 95%, 오른쪽 40%이면 전체 채움은 맞아도 분포 미달입니다. 반면 의도적으로 여백을 둔 제작에서는 구역별 목표를 다르게 정할 수 있습니다. 그 기능을 제공하기 전에는 균일 채움 기준을 자동 생성의 기본 정책으로 둡니다.

### 2.3 한 덩어리 빈 공간 — 큰 구멍 경고

구역 평균이 비슷해도 각 구역의 가운데에 큰 구멍이 남을 수 있습니다. 따라서 구역 분할과 별도로 격자 칸마다 3×3 창을 겹쳐 이동시키며 빈 공간을 확인하는 경고를 제안합니다.

초기에는 **창의 9칸이 모두 생성 대상이고 배치 가능한 경우 중, 8칸 이상이 비어 있는 위치**를 강조합니다. 영역 밖·금지 칸이 섞인 창은 이 검사에서 제외합니다. 겹치는 경고는 한 부분처럼 묶어 보여줍니다.

이 경고는 조밀한 채움에서 눈에 띄는 빈 곳을 찾는 보조 수단입니다. 빈칸을 많이 허용한 맵에서는 자연스럽게 발생할 수 있으므로 처음부터 생성 실패 조건으로 삼지 않습니다. 3×3 창이 들어가지 않는 좁은 범위에는 '검사 적용 안 됨'을 표시합니다.

### 2.4 화살 머리 분포는 별도로 봅니다

긴 몸체만 영역을 지나가면 칸은 채워져도 머리가 한쪽에 몰릴 수 있습니다. 구역별 머리 수를 같이 표시하되, 길이 구성·감싸기 의도에 따라 달라지므로 첫 단계에는 관찰용으로 둡니다. 점유 균일성과 머리 분포 균일성을 같은 판정으로 합치지 않습니다.

## 3. 입력 속성별 검증 기준

| 입력 | 실제 측정 | 판정 기준 | 보드에서 볼 근거 |
|---|---|---|---|
| 빈칸 허용도 | 전체 빈칸 비율과 구역별 점유 | 빈칸 목표 범위와 분포 기준을 각각 통과 | 덜 채워진 구역과 큰 빈 공간 |
| 크기 구성 | 신규 화살의 종류별 개수·비율 | 목표 비율을 실제 신규 수에 맞춰 정수 개수로 배분한 값과 비교 | 짧음·중간·김을 선택해 강조 |
| 꺾인 화살 비중 | 신규 화살 중 방향 전환이 있는 화살 수 | 목표 비율을 정수 개수로 환산해 비교 | 꺾인 화살만 강조 |
| 시작 선택지 수 | 최종 전체 보드에서 즉시 제거 가능한 화살 수 | 지정한 최소~최대 범위 | 실제 가능한 화살을 강조하고 코어로 제거 확인 |
| 연결 길이 | 전체 방해 관계의 최장 선행 연결 | 지정한 최소~최대 화살 수 | 최장 경로의 화살과 방해 칸 |
| 연결 참여 비중 | 목표 최소 길이 이상 경로에 속한 고유 화살 비율 | 지정한 참여 목표 범위 | 참여·비참여 화살과 구역별 분포 |

비율마다 목표와 허용 범위를 함께 보존합니다. 크기 비율은 소수 목표 개수를 구한 뒤 정수 부분을 배분하고 남은 개수를 소수 부분이 큰 종류에 나누는 방식으로 환산할 수 있습니다. 정수 배분으로 생긴 불가피한 차이와 생성기가 목표를 못 맞춘 차이를 구분합니다. 신규 화살이 0개면 신규 구성 비율은 계산 불가입니다.

연결 참여 비중이 맞아도 한쪽에만 연결이 몰릴 수 있습니다. 구역별로 참여 화살 머리 수와 전체 머리 수를 표시해 어디에 모였는지 확인합니다. 첫 구현에서는 이를 난이도 통과 조건으로 더 늘리지 않고, 제작자가 관계 강조와 함께 판단할 근거로 제공합니다.

## 4. 배치 규칙별 효과 검증

| 규칙 | 적용 사실 확인 | 효과 확인 |
|---|---|---|
| R01 크기 구성 확보 | 부족한 종류를 보충했는지 | 최종 구성 오차가 줄었는지 |
| R02 선행 연결 | 실제 출구 직선이 다른 몸체에 막히는지 | 목표 연결 길이가 생겼고 순환 없이 클리어되는지 |
| R03 연결 분산 | 여러 위치에 연결을 만들었는지 | 참여 비중과 보드의 참여 범위가 늘었는지 |
| R04 긴 화살로 감싸기 | 긴 몸체가 짧은 묶음 주변을 두르며 실제 출구를 막는지 | 해당 긴 화살 제거 전후 실제로 새로 열린 짧은 화살 수 |
| R05 빈칸 보충 | 남은 점유량을 추가했는지 | 분포가 개선되고 시작 선택지·연결 목표가 유지되는지 |

감싸는 모양만 생겼는데 짧은 화살의 출구와 만나지 않았다면 차단 효과는 없습니다. 출구를 막았더라도 다른 방해가 남아 있으면 즉시 개방은 0일 수 있습니다. 따라서 모양·차단·즉시 개방을 구분합니다. 특정 개방량을 목표로 채택한 경우에만 그 범위까지 규칙의 성공 조건에 포함합니다.

R01·R05처럼 전후 개선을 비교하는 규칙은 단계별 측정값을 남깁니다. 전후 상태 중간에 다른 변경이 섞이면 해당 규칙만의 효과라고 단정하지 않습니다.

## 5. 난이도의 체감 효과를 확인하는 작은 실험

처음부터 통합 난이도 점수를 만들지 않고 다음 절차로 확인합니다.

1. 보드 크기·생성 영역·기존 배치·채우기 목표를 같게 둡니다.
2. 시작 선택지 또는 연결 길이 등 **한 항목만** 두 수준으로 바꿉니다.
3. 각 수준에서 여러 시드로 생성합니다. 첫 점검은 같은 시드 목록 10개로 시작하고, 성공률과 목표 오차를 확인합니다. 10개 통과가 일반적인 품질을 보증하지는 않습니다.
4. 실제 채움·크기 구성이 비슷하게 나온 맵을 비교 플레이합니다. 관계만 바꿨다고 생각했는데 한쪽이 훨씬 비었다면 비교 근거가 약합니다.
5. 첫 합법 제거까지 걸린 시간, 제거 사이의 판단 시간, 막힌 화살 클릭 수와 '더 찾기 어려웠는지'를 기록합니다. 총 시간은 화살 개수와 함께 봅니다.
6. 결과가 의도와 다르면 생성 목표 미달인지, 목표는 맞았지만 효과가 없었는지 구분합니다. 전자는 생성 로직을, 후자는 속성 선택·목표 수준을 보강합니다.

같은 사람이 같은 맵을 외워서 푸는 효과를 줄이도록 제시 순서를 바꾸고 서로 다른 맵도 섞습니다. 자동 생성이 같은 시드를 받아도 설정 변경으로 다른 난수 소비 경로가 생길 수 있으므로, 시드가 같다는 이유만으로 외형도 같다고 가정하지 않습니다.

시작 선택지가 줄었는데 빨리 찾는다면 '어렵게 만들기 실패'라는 결과도 유효합니다. 값과 체감 난이도가 반대로 나오는 사례를 기록해야 속성을 실용적으로 보정할 수 있습니다.

## 6. 툴에 필요한 최소 확인 화면

기존 인스펙터의 통계 흐름을 활용해 다음을 제공합니다.

- **목표 / 실제 / 판정:** 전체 채움, 공간 분포, 크기 구성, 꺾임, 시작 선택지, 연결 길이·참여.
- **검사 근거 강조:** 덜 채워진 구역, 빈 공간 경고, 크기 종류, 제거 가능 화살, 연결 경로.
- **풀이 한 단계 전후 비교:** 제거한 화살, 새로 열린 화살, 남은 선택지 수.
- **반복 생성 결과:** 성공한 후보 수, 항목별 미달 횟수, 소요 시간. 시드·입력·검사 기준을 함께 보존.

판정을 못 한 항목은 '미검사'로 표시합니다. 오류가 없다는 이유로 분포·구성·난이도까지 통과했다고 표시하지 않습니다.

## 7. 첫 구현 순서 제안

**전체 채움 + 구역별 분포 + 구성 비중 + 규칙·클리어 검사**부터 연결합니다. 이 기준으로 무작위 채우기의 기본 품질을 확보한 다음 **시작 선택지·연결·감싸기 효과**를 확인합니다. 큰 빈 공간 경고와 반복 생성 비교를 보조로 추가합니다.

이 문서의 3×3 분할·창 크기·작은 표본 10칸·15/20%p 차이는 시험용 기준입니다. 실제 맵에서 통과했는데 보기 나쁜 사례, 미달했는데 적절한 사례를 다음 번호 문서에 기록해 기준을 보정합니다. 이번 작업은 기준 문서화이며 실행 코드 변경이나 효과 실험은 수행하지 않았습니다.
