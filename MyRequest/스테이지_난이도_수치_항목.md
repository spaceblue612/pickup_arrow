# 스테이지 난이도 수치 항목 조사

## 목적

한 스테이지의 난이도를 수치로 지정하고 관리할 수 있는 항목을 정리한다.
항목은 현재 바로 설정 가능한 값, 현재 계산 가능한 값, 추가 구현 후보,
플레이 제약, 생성 비용으로 구분한다.

난이도는 다음 다섯 축으로 관리한다.

1. 보드 규모
2. 화살 형상과 보드 밀도
3. 시각적 탐색 복잡도
4. 화살 사이의 선행 의존 관계
5. 플레이 시간과 제약

## 현재 바로 설정 가능한 항목

현재 스테이지 설정과 생성기가 지원하는 값이다.

| 항목 | 적용 범위 | 의미와 일반적인 영향 |
|---|---|---|
| `grid_width` | 현재 전역 | 보드 가로 칸 수. 커지면 탐색 공간이 넓어진다. |
| `grid_height` | 현재 전역 | 보드 세로 칸 수. 커지면 탐색 공간이 넓어진다. |
| `primary_arrow_count` | 스테이지 | 기본 화살 수. 많으면 제거 횟수와 상호작용 가능성이 증가한다. |
| `min_length` | 스테이지 | 기본 화살의 최소 길이 |
| `max_length` | 스테이지 | 기본 화살의 최대 길이 |
| `target_empty_ratio` | 스테이지 | 전체 보드의 목표 빈칸 비율. 낮을수록 조밀하다. |
| `filler_max_length` | 스테이지 | 빈칸 비율을 맞추는 보충 화살의 최대 길이 |
| `min_dependency_depth` | 스테이지 | 가장 긴 선행 제거 연쇄의 최소 길이 |
| `max_dependency_depth` | 스테이지 | 가장 긴 선행 제거 연쇄의 최대 길이 |
| `min_initial_extractable_ratio` | 스테이지 | 시작 시 제거 가능한 화살 비율의 최솟값 |
| `max_initial_extractable_ratio` | 스테이지 | 시작 시 제거 가능한 화살 비율의 최댓값 |
| `min_forced_state_ratio` | 스테이지 | 선택 가능한 화살이 하나뿐인 상태 비율의 최솟값 |
| `max_forced_state_ratio` | 스테이지 | 선택 가능한 화살이 하나뿐인 상태 비율의 최댓값 |
| `seed` | 스테이지 | 생성 결과 재현용 기준 seed. 난이도 크기를 직접 나타내지는 않는다. |
| `max_candidate_attempts` | 스테이지 | 목표 범위에 맞는 보드를 찾기 위한 후보 검사 한도 |

현재 보드 크기는 모든 스테이지가 `9x9`를 공유한다. 생성기와 분석기는 임의의
`grid_size`를 처리하지만, 스테이지마다 다른 보드 크기를 사용하려면 런타임 그리기와
스테이지 검증이 현재 스테이지의 크기를 참조하도록 변경해야 한다.

## 현재 이미 계산되는 항목

현재 생성 결과나 의존 분석 결과에서 얻을 수 있는 값이다. 일부는 selector의 목표
범위에 추가하면 바로 스테이지 채택 조건으로 활용할 수 있다.

| 항목 | 의미 | 현재 용도 |
|---|---|---|
| `node_count` | 실제 전체 화살 수 | 측정 |
| `filler_arrow_count` | 보충 화살 수 | 측정 |
| `occupied_cell_count` | 화살이 차지한 총 칸 수 | 측정 |
| `actual_empty_ratio` | 실제 빈칸 비율 | 목표 빈칸 검증 |
| `edge_count` | 화살 사이의 전체 차단 관계 수 | 측정 |
| `dependency_depth` | 가장 긴 선행 제거 연쇄 | 채택 조건 |
| `initial_extractable_count` | 시작 시 제거 가능한 화살 개수 | 측정 |
| `initial_extractable_ratio` | 시작 시 제거 가능한 화살 비율 | 채택 조건 |
| `forced_state_count` | 선택지가 하나인 상태의 횟수 | 측정 |
| `forced_state_ratio` | 선택지가 하나인 상태의 비율 | 채택 조건 |
| `average_choice_count` | 진행 중 평균 제거 가능 화살 수 | 관찰 지표 |
| `choice_counts` | 각 제거 단계의 선택지 개수 | 분석 자료 |
| `attempt_count` | 채택까지 검사한 후보 수 | 생성 비용 관찰 |
| `selected_seed` | 실제 채택된 후보 seed | 결과 재현 |

우선적으로 채택 조건에 추가할 가치가 있는 값은 다음과 같다.

- `total_arrow_count_min/max`
- `edge_count_min/max`
- `average_choice_count_min/max`
- `forced_state_count_min/max`

## 추가 구현 가능한 형상·시각 난이도

현재 화살 몸체 데이터를 이용해 계산할 수 있는 후보이다.

| 제안 항목 | 의미 |
|---|---|
| `average_arrow_length` | 전체 화살의 평균 길이 |
| `arrow_length_variance` | 짧고 긴 화살이 섞인 정도 |
| `single_cell_arrow_ratio` | 한 칸짜리 화살 비율 |
| `average_bend_count` | 화살 하나당 평균 꺾임 수 |
| `max_bend_count` | 한 화살의 최대 꺾임 수 |
| `bend_density` | 화살 길이 대비 꺾임 비율 |
| `straight_arrow_ratio` | 꺾이지 않은 화살 비율 |
| `average_exit_distance` | 화살촉에서 보드 밖까지의 평균 거리 |
| `average_blocker_distance` | 화살촉에서 첫 방해 화살까지의 평균 거리 |
| `direction_balance` | 상하좌우 방향의 편중 정도 |
| `local_density_variance` | 보드의 특정 구역에 화살이 몰린 정도 |
| `filler_ratio` | 전체 화살 중 보충 화살 비율 |
| `filler_dependency_contribution` | 보충 화살 하나가 만드는 차단 관계 수 |

시각적인 탐색 난이도에는 평균 화살 길이, 평균 꺾임 수, 한 칸 화살 비율,
구역별 밀도 편차가 특히 유효하다.

## 추가 구현 가능한 의존 관계 난이도

| 제안 항목 | 의미 |
|---|---|
| `dependency_edge_density` | 화살 수 대비 차단 관계 밀도 |
| `average_fan_in` | 화살 하나를 열기 위해 필요한 평균 선행 화살 수 |
| `max_fan_in` | 하나의 화살을 막는 최대 화살 수 |
| `average_fan_out` | 화살 하나가 막는 평균 후속 화살 수 |
| `max_fan_out` | 열쇠 화살 하나가 막는 최대 후속 화살 수 |
| `key_arrow_count` | 여러 화살을 여는 핵심 화살 수 |
| `average_unlock_gain` | 화살 제거 한 번당 새로 열리는 평균 화살 수 |
| `max_unlock_gain` | 화살 하나를 제거했을 때 새로 열리는 최대 화살 수 |
| `dependency_component_count` | 서로 독립된 맞물림 묶음 수 |
| `largest_component_ratio` | 가장 큰 맞물림 묶음의 전체 화살 비율 |
| `region_count` | 보드를 나누는 퍼즐 지역 수 |
| `module_size_min/max` | 맞물림 모듈 하나에 포함되는 화살 수 |
| `cross_region_gate_count` | 지역 사이를 연결하는 의존 관계 수 |
| `max_forced_chain_length` | 선택지가 하나인 상태가 연속되는 최대 길이 |
| `choice_count_min/max` | 진행 중 최소·최대 선택지 수 |
| `choice_count_variance` | 단계별 선택지 수의 변화 정도 |
| `solution_branch_count` | 가능한 제거 순서 수 또는 추정치 |
| `solution_entropy` | 제거 순서의 분기 다양성을 정규화한 값 |

현재 규칙에서는 제거 가능한 화살을 제거해도 다른 화살이 새로 막히지 않는다.
따라서 많은 해답 분기는 실패 위험보다는 선택의 자유와 탐색량을 나타낸다.

## 플레이 시간·제약 항목

배치 구조가 아니라 시간 압박이나 실수 제한으로 난이도를 부여하는 후보이다.

| 제안 항목 | 현재 상태 |
|---|---|
| `time_limit_seconds` | 미구현 |
| `blocked_tap_limit` | 미구현 |
| `mistake_penalty_seconds` | 미구현 |
| `hint_count` | 미구현 |
| `hint_cooldown_seconds` | 미구현 |
| `extraction_speed_pixels_per_second` | 전역 구현 |
| `stage_clear_delay_seconds` | 전역 상수 |
| `blocked_feedback_duration_seconds` | 전역 상수 |

추출 속도와 피드백 시간은 논리 난이도보다는 템포와 접근성에 가깝다. 핵심 난이도
점수에는 섞지 않고 별도 플레이 설정으로 관리하는 편이 좋다.

## 생성 품질·비용 항목

다음 값은 플레이 난이도가 아니라 원하는 스테이지를 생성하는 데 사용할 계산량을
결정한다. `generation_budget`으로 분리해서 관리한다.

- `max_candidate_attempts`
- `max_board_attempts`
- `max_arrow_attempts`
- `metric_tolerance`
- `module_retry_limit`
- `candidate_seed_step`

## 권장 스테이지 프로필

```yaml
board:
  width: 9
  height: 9
  target_empty_ratio: 0.40

arrows:
  total_count: [7, 10]
  primary_count: 5
  length: [5, 14]
  average_length: [6.0, 10.0]
  filler_max_length: 3
  bend_count: [1, 5]
  single_cell_ratio: [0.0, 0.15]

dependency:
  depth: [4, 8]
  initial_extractable_ratio: [0.15, 0.35]
  forced_state_ratio: [0.20, 0.50]
  average_choice_count: [1.5, 3.0]
  edge_density: [0.10, 0.30]
  max_fan_in: 3
  max_fan_out: 4
  max_forced_chain_length: 3

generation_budget:
  max_candidate_attempts: 64
```

이 예시 중 현재 selector가 직접 채택 조건으로 지원하는 값은 `depth`,
`initial_extractable_ratio`, `forced_state_ratio`이다. 나머지는 구현 후보이다.

## 적용 우선순위

1. 현재 핵심: 보드 크기, 빈칸 비율, 전체 화살 수, 길이 범위
2. 논리 난이도: 의존 깊이, 초기 제거 가능 비율, 평균 선택지 수, 강제 상태 비율
3. 맞물림 성격: `fan_in`, `fan_out`, 의존 간선 밀도
4. 시각 난이도: 평균 꺾임 수, 한 칸 화살 비율, 지역별 밀도
5. 후속 확장: 지역·모듈·관문 수, 시간 제한, 힌트 제한

## 해석 시 주의점

- 보드 크기는 화살 수와 밀도가 함께 증가하지 않으면 난이도가 반드시 높아지지 않는다.
- 빈칸 비율이 낮으면 차단 관계가 늘기 쉽지만 생성 실패와 순환 위험도 증가한다.
- 화살 수가 많으면 플레이 시간이 늘지만 논리 난이도가 반드시 높아지지는 않는다.
- 긴 화살은 시각 복잡도와 차단 가능성을 늘리지만, 같은 점유율에서는 전체 화살 수를 줄일 수 있다.
- `initial_extractable_ratio`가 낮으면 첫 선택지가 제한되지만 풀이를 더 쉽게 안내할 수도 있다.
- `forced_state_ratio`가 높으면 순서 강제성은 증가하지만 선택 부담이 줄어 오히려 쉬워질 수 있다.
- `average_choice_count`가 높아도 현재 규칙에는 잘못된 합법 수가 없으므로 실패 가능성보다 탐색의 자유를 의미한다.
- 단일 `difficulty_score`만 저장하기보다 원시 수치를 범위로 관리하고, 난이도 프리셋이 여러 수치를 조합하도록 만드는 편이 안전하다.

## 관련 구현

- `scripts/stage_catalog.gd`: 현재 스테이지별 생성·난이도 설정
- `scripts/arrow_placement.gd`: 화살 형상과 밀도 생성
- `scripts/dependency_analyzer.gd`: 의존 관계 및 해결 과정 분석
- `scripts/dependency_targeting.gd`: 의존 목표 범위에 맞는 후보 선택
- `scripts/main.gd`: 추출 속도와 플레이 피드백
- `MyRequest/레벨_난이도_적용_가이드.md`: 현재 구현의 적용 방법
- `MyRequest/요구사항2_브레인스토밍_결과.md`: 지역·모듈·의존 그래프 확장 아이디어
