# 자동 배치의 채우기 설정과 난이도 속성 조사

조사일: 2026-10-29  
상태: 공개 구현·연구와 현재 코드를 비교한 설계 참고 자료입니다. 아래 신규 속성은 구현 완료나 체감 난이도 검증을 뜻하지 않습니다.

## 1. 분류 결론

사용자 설정은 다음 두 묶음으로 나눕니다.

1. **채우기 설정:** 어디에, 얼마나, 어떤 크기와 모양의 화살을 배치할지 정합니다.
2. **난이도 설정:** 화살 사이의 방해 관계, 다음 화살을 찾는 부담, 풀이 중 열리는 흐름을 정합니다.

시드·시간 제한·후보 시도 횟수는 생성 실행 설정으로 별도 관리합니다. 이 값들은 난이도를 표현하지 않습니다. 클리어 가능 여부는 반드시 통과할 조건입니다.

두 묶음은 영향을 주고받습니다. 조밀한 배치는 방해 관계를 만들 공간을 늘리고 긴 화살은 여러 경로를 막을 수 있습니다. 따라서 분류는 설정 목적을 구분하는 것이며, 서로 독립적으로 어떤 값이든 달성할 수 있다는 뜻은 아닙니다.

## 2. 조사한 공개 구현과 다른 퍼즐

### 2.1 Go Arrows — 몸체 성장과 결과 검사

공개 코드에서는 짧은 화살들을 먼저 놓고 꼬리를 빈 이웃 칸으로 성장시킵니다. 직진과 꺾임이 모두 가능할 때 직진을 선호하는 확률이 있습니다. 생성 후 시작 시 제거 가능한 화살 비율과 클리어 가능 여부를 검사합니다. [성장 코드](https://github.com/sergev/goarrows/blob/main/game/gen_grow.go), [생성·채택 코드](https://github.com/sergev/goarrows/blob/main/game/gen.go)

**적용 해석:** 몸체가 채워지는 성향과 결과 보드의 풀이 구조를 구분할 근거가 됩니다. 이 프로젝트에서는 길이·꺾임은 채우기에, 시작 선택지 수는 난이도에 둡니다. 해당 구현의 직진 확률이나 시작 선택지 기준을 그대로 가져올 근거는 없습니다.

### 2.2 Arrows Escape Web — 역순 구성과 길이·꺾임 분포

공개 생성기는 화살을 추가할 때 몸체가 겹치지 않고 새 머리의 출구 경로가 비어 있는지 확인합니다. 추가 순서의 역순이 제거 순서가 됩니다. 설정 코드에는 보드 크기·화살 수 범위와 길이별·꺾임 횟수별 가중치가 있습니다. README의 수치보다 실제 설정 파일을 기준으로 확인했습니다. [생성 코드](https://github.com/JasonDistler/arrows-escape-web/blob/master/src/engine/generator.js), [설정 코드](https://github.com/JasonDistler/arrows-escape-web/blob/master/src/config.js)

**적용 해석:** 길이 최솟값·최댓값만 지정하는 것보다 짧음·중간·김의 비중을 지정하면 외형을 예측하기 쉽습니다. 역순 구성은 풀이 가능성을 유지하는 방법이며 그 자체로 난이도 목표 달성을 보장하지 않습니다. 기존 수동 화살이 있는 경우에는 전체 보드를 다시 검사해야 합니다.

위 두 자료는 공개된 독립 구현입니다. 상용 원작의 내부 생성 로직이나 난이도 공식이 공개되었다는 뜻은 아닙니다. 외부 코드를 실행하거나 프로젝트에 복사하지 않았습니다.

### 2.3 스도쿠 — 각 단계의 판단과 단계 사이의 의존

Pelánek의 연구는 인간 풀이 자료를 이용해 개별 풀이 단계의 복잡성과 단계 사이의 의존 구조를 함께 다룹니다. 진행 가능한 선택지의 수와 여러 실행의 평균을 분석하며, 전체 풀이의 단일 정적 수치만으로 설명하기 어려운 차이를 보여줍니다. [논문 본문](https://arxiv.org/html/1403.7373v1)

**적용 해석:** 화살 게임에서도 시작 선택지 하나보다 풀이 중 선택지 변화가 유용한 후보입니다. 다만 스도쿠의 추론 기법이나 연구에서 사용한 임계값을 화살 게임에 그대로 적용하지 않습니다.

### 2.4 소코반 — 단순 밀도보다 실제 방해 관계

Kartal 등의 연구는 보드 구성과 시뮬레이션을 이용한 생성, 사용자 비교 평가를 통한 지표 선택을 다룹니다. 공간 배치·상자 수·경로 혼잡을 비교하며, 단순히 근처에 장애물이 있는 경우와 실제 이동 관계가 혼잡한 경우를 구별하도록 지표를 개선합니다. [논문](https://ojs.aaai.org/index.php/AIIDE/article/download/12859/12706/16375)

**적용 해석:** 화살 게임에서도 전체 점유율보다 실제 탈출 경로를 막는 화살의 수와 관계를 난이도 후보로 둡니다. 소코반의 막다른 상태와 되돌리기 부담은 현재 화살 규칙과 달라 직접 이식하지 않습니다.

## 3. 이 프로젝트 규칙에서 먼저 지켜야 할 해석

현재 [경로 판정](../scripts/path_rule.gd)은 머리 앞에서 보드 경계까지의 직선에 있는 화살 ID를 수집합니다. 같은 방해 화살이 여러 칸을 차지해도 한 화살로 셉니다.

- 제거는 점유 칸을 없애므로, 제거 가능했던 다른 화살을 새로 막지 않습니다.
- 클리어 가능한 보드에서 합법적인 화살을 고르는 것은 실패 분기를 만들지 않습니다. 가능한 제거 순서가 많다는 이유로 더 어렵다고 판단하면 안 됩니다.
- 선택지가 하나인 긴 구간은 찾기 어렵게 만들 수도 있지만, 한 번 알아낸 후에는 쉽게 반복하는 구간일 수도 있습니다.
- 다중 차단과 긴 연쇄는 서로 다른 속성입니다. 여러 독립 화살을 먼저 치우는 구조와 차례대로 이어진 구조를 구분해야 합니다.
- 금지 칸은 현재 배치 금지 용도입니다. 탈출 경로를 막는 벽으로 해석하지 않습니다.
- 화살의 영역 소속은 현재 도구와 같이 **머리 좌표**로 판단합니다. 몸체 전체가 해당 영역 안에 있다는 뜻은 아닙니다.

따라서 아래 난이도 속성은 주로 **탐색 부담·관계 파악·풀이 리듬의 조절값**입니다. 잘못된 합법 선택을 찾아내는 탐색 깊이로 설명하지 않습니다.

## 4. 채우기 설정

아래 이름은 의미를 분명히 하기 위한 제안이며 저장 형식 확정안은 아닙니다.

| 속성 | 단위·정의 | 권장 입력 방식 | 기존 기능 활용 |
|---|---|---|---|
| 생성 범위 | 전체 보드 또는 선택 영역의 칸 집합 | 전체/영역 선택 | 영역 데이터 활용 가능, 생성 연결은 추가 필요 |
| 보드 크기 | 가로·세로 칸 수 | 정수 두 개 | 기존 생성기 지원 |
| 빈칸 허용도 | 범위 내 배치 가능 칸 중 생성 후 비어 있어도 되는 비율 | 목표 비율과 허용 오차 | 기존 목표 빈칸 비율 확장 |
| 화살 길이 분포 | 화살 하나의 칸 수와 길이별 비중 | 최소·최대와 짧음/중간/김 비중 | 기존 길이 범위 활용, 분포 제어 추가 |
| 꺾임 분포 | 화살 하나의 직각 방향 전환 횟수 | 직선/1회/2회 이상 비중과 최대 횟수 | 기존 모양 생성·측정 활용 가능 |
| 배치 방향 비중 | 머리 방향별 화살 수 비중 | 상·하·좌·우 가중치 | 기존 방향 생성 활용, 가중치 제어 추가 |
| 공간 분포 | 특정 부분만 비거나 과도하게 몰리는 정도 | 균등 성향 또는 영역별 채우기 목표 | 기존 중앙·분할 구역 점유 측정 활용 |
| 화살 수 | 기존 수와 신규 수를 구분한 개수 | 추가 개수 지정이 필요할 때 선택 | 기본 수·보충 수 구조의 재정의 필요 |

### 빈칸 허용도의 계산

생성 범위의 칸 집합을 S, 금지 칸을 제외한 집합을 P, 생성 후 화살이 점유한 고유 칸 집합을 O라고 합니다.

`빈칸 비율 = |P에서 O를 제외한 칸| / |P|`

기존 화살이 범위 안에서 차지한 칸도 O에 포함합니다. 범위 밖 칸과 금지 칸을 분모에 넣지 않습니다. P가 비어 있으면 계산 불가·생성 불가로 처리합니다.

예를 들어 배치 가능 칸 100개에 기존 화살이 30칸을 차지하고 목표 점유가 80%라면, 추가 목표는 약 50칸입니다. 남은 70칸의 80%를 추가하는 의미가 아닙니다. '남은 공간 기준 추가량'이 필요하면 별도 입력으로 구별해야 합니다.

### 수량 조건의 충돌

화살 수·길이·빈칸 비율을 동시에 정확한 값으로 고정하면 달성할 수 없는 경우가 생깁니다. 신규 화살 K개, 길이 Lmin~Lmax라면 신규 점유 칸은 최소한 K×Lmin~K×Lmax 범위에 있어야 합니다. 이 범위를 만족해도 형상·방해 관계 때문에 배치가 불가능할 수 있습니다.

기본 조작은 빈칸 허용도와 길이 분포로 채우고 화살 수를 결과로 보는 방식을 권장합니다. 추가 개수를 지정하는 작업에서는 길이·점유 목표의 허용 범위를 함께 보여줘야 합니다. 기존 수동 화살의 최소 길이는 제작 규칙인 2칸을 따르며, 게임 생성기의 과거 1칸 허용을 그대로 도입하지 않습니다.

## 5. 난이도 설정 후보

### 5.1 상태와 풀이 경로에 따른 수치

풀이 단계 t에서 남은 화살 집합을 R(t), 바로 제거 가능한 집합을 A(t)라고 합니다.

| 속성 | 측정 정의 | 조절할 경험·한계 |
|---|---|---|
| 시작 선택지 수 | A(0)의 개수. 시작 선택지 비율도 병기 | 처음 찾을 수 있는 출발점 수를 조절 |
| 진행 중 선택지 범위 | 각 단계의 A(t) 개수, 구간별 최솟값·중앙값 | 선택 폭과 탐색 부담. 전체 평균 하나로 대체하지 않음 |
| 탐색 대상 비율 | A(t)의 개수 / R(t)의 개수 | 남은 화살 중 실제로 뺄 수 있는 비중. 개수와 함께 봐야 함 |
| 압박 커버리지 | A(t)의 개수≤q인 평가 단계 수 / 전체 평가 단계 수 | 선택지가 적은 구간의 비중. q는 명시적으로 설정 |
| 압박 지속 길이 | 압박 조건이 연속되는 제거 단계 수 | 짧은 막힘과 긴 압박을 구분. 최대·중앙값 표시 |
| 압박 발생 횟수 | 연속 압박 구간을 한 사건으로 센 개수 | 압박이 여러 번 돌아오는 흐름. 최소 사건 길이와 구간 사이 간격도 정의 |
| 즉시 개방량 | a 제거 후 A(t+1)에서 A(t)와 a를 제외한 새 화살 수 | 제거 한 번으로 생기는 보상·갈림. 큰 값이 더 어렵다는 뜻은 아님 |

끝에 한 화살만 남은 상태를 무조건 압박으로 세면 모든 맵에 압박이 생깁니다. 평가할 진행 범위와 최소 잔여 수를 별도 지정하고, 제외된 마지막 구간도 원본 그래프에서는 볼 수 있게 합니다. q나 평가 종료 지점을 '검증된 난이도 공식'처럼 고정하지 않습니다.

### 5.2 제거 순서에 덜 의존하는 구조 수치

방해 화살 b를 먼저 제거해야 a가 열리는 관계를 `b → a`로 표현합니다.

| 속성 | 측정 정의 | 조절할 경험·한계 |
|---|---|---|
| 다중 차단 비율 | 서로 다른 방해 화살이 2개 이상인 화살 수 / 전체 화살 수 | 한 개만 제거해도 열리는 구조와 구별. 초기값과 진행값 구별 |
| 선행 필요 수 | a를 열기 위해 먼저 제거해야 하는 모든 선행 화살의 고유 개수 | 즉시 방해 수와 구별. 겹치는 선행 화살은 한 번만 셈 |
| 연쇄 깊이 분포 | 각 화살의 최장 선행 경로 길이별 개수·비율 | 최장 연결 하나가 전체를 대표하는 문제 완화. 시작점 깊이는 0, 연결은 간선 수로 명시 |
| 연결 묶음 수·크기 | 방향을 무시했을 때 방해 관계로 연결되는 묶음 수와 각 크기 | 독립 퍼즐이 여러 개인지, 한 구조로 얽혔는지 구분 |
| 영역 간 의존 비율 | 머리 소속 영역이 다른 화살 사이의 방해 관계 수 / 전체 방해 관계 수 | 영역 사이의 상호작용 조절. 영역 미지정 관계는 별도 집계 |

방해 관계가 없을 때 비율의 분모가 0이면 0 또는 해당 없음 중 표시 규칙을 고정합니다. 연쇄 깊이는 기존 분석기가 시작점을 1로 세므로, 화면·저장 규약과 변환을 명시해야 합니다.

### 5.3 관문과 영역 개방

영역 r의 남은 화살은 머리가 r 안에 있는 화살이며, 관문 g를 제거하기 전후의 해당 영역 제거 가능 수 차이를 측정합니다. g 자신은 새로 열린 화살 수에서 제외합니다.

- **관문 직후 개방량:** 실제로 g를 제거할 수 있는 상태에서, 제거 전후 새롭게 열린 영역 화살 수.
- **관문까지 필요한 선행 수:** g의 모든 선행 화살의 고유 개수. 관문 자체 제거는 별도 1회입니다.
- **영역 개방 순서:** 여러 영역의 개방 사건이 어느 풀이 단계에 나타나는지.

현재 '영역 개방' 화면의 수치는 해당 영역에서 지금 제거 가능한 화살 수입니다. 관문 효과를 측정한 값으로 바꾸어 해석하면 안 됩니다. 또한 g가 많은 화살을 막아도, 그 화살에 다른 방해가 남아 있으면 즉시 개방량은 작거나 0일 수 있습니다.

### 5.4 시각적 탐색 부담 — 우선 관찰용

| 후보 | 계산 제안 | 취급 |
|---|---|---|
| 머리와 첫 방해물 사이 거리 | 막힌 화살 머리부터 가장 가까운 방해 칸까지의 격자 거리 분포 | 먼 방해를 알아보기 어려운지 검증 필요 |
| 가능한 화살의 흩어짐 | 제거 가능한 머리 좌표의 정규화된 거리·분포 | 넓게 흩어지면 찾기 어려운지 단정 불가 |
| 머리 주변 혼잡 | 머리 주변 일정 반경의 다른 화살 점유 비율 | 화면 확대율·선 굵기·색 영향까지 기록 필요 |

이 지표들은 채우기 속성과 겹치는 영향이 큽니다. 처음부터 생성의 필수 조건으로 늘리지 않고, 플레이 자료와 함께 의미를 확인하는 것이 좋습니다.

## 6. 계산 가능성과 생성 제어 가능성의 구분

| 묶음 | 현재 재사용할 수 있는 코드 | 필요한 확장 |
|---|---|---|
| 크기·길이·밀도·금지 칸 | `arrow_placement.gd`, `stage_catalog.gd` | 도구의 전체/부분 생성 요청 연결, 기존 배치 보존 |
| 모양·분포 | `generation_quality.gd` | 길이·꺾임 분포와 목표별 결과 표시 |
| 선택지·풀이 순서 | `dependency_analyzer.gd` | 압박 구간·즉시 개방량·구간별 통계 |
| 선행 관계 | `blockers_by_arrow`, `dependents_by_arrow` | 선행 고유 개수·깊이 분포·연결 묶음 |
| 영역·관문 | 도구의 영역 칸·역할 메타데이터 | 전체 보드 관계와 영역을 연결한 효과 분석 |
| 후보 비교 | `dependency_targeting.gd` | 새 목표 평가·목표 미달 표시·생성의 구조적 유도 |

위 확장은 코드 재사용 가능성의 평가입니다. 측정할 수 있다고 해당 수치를 원하는 범위로 빠르게 생성할 수 있는 것은 아닙니다. 예를 들어 압박 사건을 여러 번 만들려면 단순 후보 필터를 넘어 방해 관계를 유도하는 생성 변경이 필요할 수 있습니다.

현재 후보 선택은 일부 조건이 목표에 못 미쳐도 가장 가까운 클리어 가능 후보를 반환할 수 있습니다. 새 도구에서도 **규칙 유효 / 클리어 가능 / 채우기 목표 달성 / 난이도 목표 달성**을 별도로 표시해야 합니다. 과거 `forced_state_ratio`는 설정과 측정값이 있지만 현재 목표 비교에는 반영되지 않는 점도 이식 시 정리해야 합니다.

## 7. 전체 생성과 영역 생성의 적용 기준

영역 안에 새 화살을 넣어도 영역 밖의 화살이 길을 막을 수 있습니다. 추가되는 몸체는 생성 범위 안에 두되, 탈출·순환 의존·클리어 검사는 전체 보드에서 수행해야 합니다.

채우기 결과에는 **범위 안의 기존 점유 + 신규 점유**를 사용합니다. 난이도 결과에는 **전체 보드 값 + 선택 영역 값**을 함께 구분합니다. 영역에 제거 가능한 화살이 0개여도 영역 밖 선행 화살을 제거하면 풀릴 수 있으므로, 이를 곧바로 실패로 판정하지 않습니다.

기존 배치를 보존한 생성은 기존 화살의 좌표·ID·모양을 바꾸지 않아야 합니다. 채우기 부족을 해결하려고 기존 화살을 자동으로 늘리거나 줄이는 기능은 별도 작업으로 취급합니다.

## 8. 측정 신뢰도와 채택 기준

현재 분석기는 배열에서 먼저 발견하는 제거 가능 화살을 고릅니다. 이 순서는 플레이어의 선택을 대표하지 않으며, 화살 배열 순서만 달라져도 경로 통계가 달라질 수 있습니다.

초기에는 경로 이름·선택 정책을 기록한 단일 경로 분석을 제공하고, 난이도 평가를 확장할 때는 무작위 합법 선택·개방량 우선 선택 등 여러 정책으로 반복 측정하는 방식을 제안합니다. 반복 수·분석 시드·관측 최솟값/중앙값/최댓값을 보존합니다. 표본의 최댓값을 모든 경로의 최댓값으로 표시하지 않습니다.

지표 검증에는 보드 크기·점유율·길이 분포를 비슷하게 유지하고 관계 구조를 바꾼 비교 맵을 사용합니다. 첫 합법 제거까지 걸린 시간, 합법 제거 사이 대기 시간, 막힌 화살 클릭·힌트 사용과 주관 평가를 비교하면 탐색 부담과 단순 작업량을 나누어 볼 수 있습니다. 총 클리어 시간만으로 보정하면 화살 수가 많은 맵을 무조건 어렵다고 평가하기 쉽습니다.

초기 핵심 속성으로는 **선택지 수 변화, 압박 길이·커버리지, 다중 차단 비율, 연쇄 깊이 분포, 즉시 개방량**을 권장합니다. 영역별 관문 효과는 영역 제작 흐름에 연결하고, 시각 지표는 검증 후 채택합니다. 이 우선순위와 공식은 공개 사례를 바탕으로 한 본 프로젝트용 제안이며, 다른 게임에서 검증된 공식의 직접 이식이 아닙니다.

## 9. 코드 확인 근거

- [경로 판정](../scripts/path_rule.gd): 머리 앞의 직선 방해 화살, 중복 ID 제거.
- [무작위 배치](../scripts/arrow_placement.gd): 길이·빈칸 목표·금지 칸·풀이 순서 생성.
- [의존 분석](../scripts/dependency_analyzer.gd): 방해 관계·최장 깊이·선택지 기록과 고정 순서 시뮬레이션.
- [생성 품질](../scripts/generation_quality.gd): 중앙·구역 점유, 긴 화살·꺾인 화살·복잡 화살 측정.
- [후보 선택](../scripts/dependency_targeting.gd): 목표 비교와 가장 가까운 후보 반환.
- [현재 도구](../tool/src/renderer.tsx): 머리 좌표에 의한 영역 소속과 현재 영역 제거 가능 수.

문서 작성 과정에서 위 로컬 코드와 연결된 외부 원문을 읽어 비교했습니다. 실행 코드·생성 설정은 변경하지 않았으며, 이번 조사를 위한 게임 테스트는 실행하지 않았습니다.
