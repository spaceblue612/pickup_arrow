# 화살 맞물림 난이도 제어 브레인스토밍 결과

## 핵심 결론

맞물림 난이도는 화살 수나 보드 점유율만으로 안정적으로 제어하기 어렵습니다. 화살을 노드, “A를 먼저 제거해야 B가 이동 가능함”을 `A → B` 간선으로 보는 **선행 의존 그래프**를 별도 난이도 모델로 두는 것이 적합합니다.

현재 규칙에서는 이동 가능한 화살을 제거하면 다른 화살의 길을 새로 막을 수 없습니다. 따라서 잘못된 합법 수로 보드가 더 어려워지는 구조가 아니라, 매 상태에서 **이동 가능한 화살을 얼마나 적게 노출하는가**와 **몇 단계의 선행 제거를 요구하는가**가 실제 난이도를 결정합니다.

## 권장 생성 구조

### 1. 지역 단위로 나누기

보드를 2~4개 지역으로 나누고 각 지역에 독립적인 맞물림 모듈을 먼저 배치합니다. 전체 보드를 한 번에 맞물리게 만드는 대신 지역별 실패만 다시 생성할 수 있어 생성 비용과 실패율을 줄일 수 있습니다.

### 2. 맞물림 모듈 사용하기

- `CHAIN`: `A → B → C`처럼 제거 순서를 길게 만드는 연쇄형
- `FAN_OUT`: 하나의 선행 화살이 2~5개 화살을 동시에 여는 열쇠형
- `FAN_IN`: 여러 선행 화살을 모두 제거해야 하나가 열리는 합류형
- `REGION_GATE`: 한 지역의 마지막 화살이 다음 지역의 첫 화살을 여는 관문형
- `FREE_CHOICE`: 처음부터 이동 가능한 화살을 일부 제공하는 선택 여유형

모듈은 회전·대칭·위치 이동이 가능한 작은 템플릿으로 만들고, 배치 실패 시 보드 전체가 아니라 해당 모듈만 다시 배치하는 방식을 권장합니다.

### 3. 그래프를 먼저 만들고 형상을 배치하기

현재 방식처럼 형상을 무작위 배치한 뒤 해결 가능성만 검사하면, 원하는 난이도가 나올 때까지 전체 생성을 반복해야 합니다. 다음 순서가 더 안정적입니다.

1. 목표 난이도 수치로 비순환 선행 의존 그래프를 만듭니다.
2. 그래프를 지역별 모듈로 나눕니다.
3. 각 모듈을 실제 격자 형상으로 배치합니다.
4. 지역 사이에 제한된 수의 관문 간선을 추가합니다.
5. 짧은 보충 화살을 넣습니다.
6. 최종 그래프 지표와 해결 가능성을 검사하고 허용 오차 밖인 모듈만 재배치합니다.

## 제안 수치

| 수치 | 의미 | 난이도에 미치는 영향 |
|---|---|---|
| `region_count` | 독립·반독립 지역 수 | 많을수록 탐색 범위가 넓어짐 |
| `module_size_min/max` | 모듈당 화살 수 | 클수록 국소 관계가 복잡해짐 |
| `dependency_depth` | 가장 긴 선행 제거 단계 | 길수록 연쇄 풀이가 길어짐 |
| `initial_extractable_ratio` | 시작 시 이동 가능한 화살 비율 | 낮을수록 첫 수 찾기가 어려움 |
| `forced_state_ratio` | 해결 과정 중 이동 가능 화살이 1개뿐인 상태 비율 | 높을수록 순서 강제성이 커짐 |
| `average_choice_count` | 각 상태의 평균 이동 가능 화살 수 | 낮을수록 강제성이 커짐 |
| `fan_out_max` | 하나가 동시에 여는 최대 화살 수 | 높을수록 열쇠 화살의 중요도가 커짐 |
| `fan_in_max` | 하나를 열기 위해 필요한 최대 선행 화살 수 | 높을수록 합류 조건이 복잡해짐 |
| `cross_region_gate_count` | 지역 사이의 선행 관계 수 | 높을수록 전체 보드 결합도가 커짐 |
| `metric_tolerance` | 목표 지표 허용 오차 | 낮을수록 생성 비용이 커짐 |
| `module_retry_limit` | 모듈별 재배치 횟수 | 생성 시간의 상한을 제어함 |

## 초기 난이도 프로필 제안

아래 값은 설계 단계에서 플레이 테스트로 조정할 출발값입니다.

| 프로필 | 지역 | 의존 깊이 | 시작 이동 가능 비율 | 강제 상태 비율 | 최대 동시 해제 | 지역 관문 |
|---|---:|---:|---:|---:|---:|---:|
| 쉬움 | 2 | 2~3 | 35~55% | 10~30% | 2 | 0 |
| 보통 | 2~3 | 4~6 | 20~35% | 35~60% | 3 | 1 |
| 어려움 | 3~4 | 6~10 | 8~20% | 60~85% | 4~5 | 1~2 |

단일 점수도 제공할 수 있지만, 생성기는 위 원시 지표를 직접 받는 편이 좋습니다. 편집 화면이나 스테이지 데이터에서만 `difficulty_score`를 프리셋으로 변환하면 원인을 추적하고 밸런스를 수정하기 쉽습니다.

## 현재 길이·빈칸 수치와의 결합

- 긴 화살은 이동 경로가 넓어 여러 화살을 막을 가능성이 커지므로 `fan_out`과 의존 깊이에 영향을 줍니다.
- 낮은 빈칸 비율은 충돌 수를 늘리지만 순환 의존과 생성 실패도 함께 늘릴 수 있습니다.
- 보충 화살은 목표 점유율을 맞추는 과정에서 의도하지 않은 맞물림을 만들 수 있습니다.
- 따라서 길이와 빈칸 비율로 형상을 만든 뒤 난이도를 추정하는 방식보다, 의존 그래프를 먼저 만들고 보충 화살까지 넣은 최종 그래프를 다시 측정하는 방식이 안전합니다.
- 보충 화살에는 `max_dependency_contribution` 같은 제한을 두어, 하나의 보충 화살이 지나치게 많은 화살을 막지 못하게 하는 것이 좋습니다.

## 구현 후보

### 후보 A: 분석·거절 방식

기존 무작위 배치를 유지하고, 생성된 보드의 의존 그래프 지표가 목표 범위에 들 때만 채택합니다.

- 장점: 현재 코드 변경이 작고 빠르게 시험할 수 있습니다.
- 단점: 어려운 프로필이나 높은 점유율에서 전체 재시도가 급증합니다.
- 용도: 지표 검증용 첫 프로토타입

### 후보 B: 모듈 템플릿 방식

연쇄형·열쇠형·합류형 템플릿을 지역별로 배치하고 일부 관문으로 연결합니다.

- 장점: 생성 결과와 난이도를 예측하기 쉽고 지역 단위 재배치가 가능합니다.
- 단점: 템플릿 라이브러리와 회전·대칭 배치기가 필요합니다.
- 용도: 짧은 기간에 통제 가능한 스테이지 생성

### 후보 C: 그래프 우선 합성 방식

목표 의존 그래프를 먼저 만든 뒤 이를 만족하는 화살 형상을 탐색합니다.

- 장점: 수치 제어가 가장 정확하고 장기 확장성이 좋습니다.
- 단점: 형상 합성기와 제약 해결 비용이 큽니다.
- 용도: 장기 자동 생성 시스템

## 권장 단계

1. 다음 스프린트에서 후보 A로 의존 그래프 분석기와 지표 측정을 먼저 구현합니다.
2. 측정값과 실제 체감 난이도의 상관관계를 플레이 테스트로 확인합니다.
3. 효과가 확인되면 후보 B의 지역·모듈 템플릿 생성기로 전환합니다.
4. 대량 자동 생성이 필요해질 때만 후보 C를 검토합니다.

현재 스프린트에서 바로 생성 구조까지 확장하기보다 **추후 별도 스프린트로 진행**하는 것을 권장합니다. 이번 구현에서 길이 범위와 빈칸 비율이라는 기초 수치가 추가되었으므로, 이를 먼저 실행해 본 뒤 의존 지표를 결합하면 변경 원인과 난이도 효과를 구분할 수 있습니다.
