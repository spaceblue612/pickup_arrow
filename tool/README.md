# Arrow Studio — 첫 실행 버전

Discord 시안을 실제 Electron + React + TypeScript 앱으로 옮긴 초기 개발판입니다. 생성·게임 반영까지 완성한 버전이 아닙니다.

## 실행

저장소 루트에서:

```bash
cd tool
npm ci
npm start
```

Godot 4.7.1 실행 파일이 `godot`으로 실행 가능해야 합니다. 그렇지 않으면 앱 오른쪽 위 설정에서 Godot 실행 파일과 프로젝트 절대 경로를 지정합니다. 현재 검증 환경은 Node 22.22.1입니다. 첫 Electron 실행 시 공식 바이너리 다운로드에 네트워크가 필요할 수 있습니다.

오른쪽 위 **에디터 환경설정 → 기준 글자 크기**에서 `−1px`·`+1px` 버튼으로 조정하고 `기본값`으로 되돌릴 수 있습니다. 기준 본문 크기는 최소 13px·기본 15px·최대 19px이며 나머지 글자는 상대적인 크기 차이를 유지합니다. 즉시 미리 보며 **환경설정 저장** 후 재실행해도 유지됩니다. 저장 없이 닫으면 저장된 크기로 돌아갑니다. Godot 경로는 같은 창의 **Godot 연결 설정**을 펼쳐 지정합니다.

### Ubuntu의 앱 전용 샌드박스 허용 설정

2026-10-20 이 컴퓨터에 `/etc/apparmor.d/arrow-studio`를 설치·활성화하여 일반 실행을 확인했습니다. 이제 위의 `npm start`를 사용하며 `--no-sandbox`는 필요하지 않습니다. 기본 앱은 `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`를 유지합니다.

프로필 원본은 [linux/apparmor/arrow-studio](linux/apparmor/arrow-studio)입니다. 허용 대상은 다음 **실행 파일 한 곳**이며 와일드카드를 사용하지 않습니다.

```text
/home/mantie/workspaces/00_games/PickupArrow/tool/node_modules/electron/dist/electron
```

Ubuntu 전체의 `kernel.apparmor_restrict_unprivileged_userns=1`은 그대로 유지하고 이 실행 파일의 사용자 네임스페이스 사용만 허용했습니다. root 소유·0644 권한의 설정 파일이므로 재부팅 후에도 유지됩니다. 같은 경로에서 의존성을 다시 설치해도 경로 기반 설정은 유지되지만, 프로젝트를 이동하거나 다른 PC를 사용하면 경로를 수정해 다시 설치해야 합니다. 다른 사용자가 이 개발 실행 파일을 교체할 수 없도록 프로젝트 접근 권한을 관리해야 합니다. 이는 [Chromium 공식 안내의 2번 방식](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)에 해당하며 별도 설치형 배포판을 구성한 것은 아닙니다.

다른 Ubuntu PC에 적용할 때는 원본 프로필의 경로를 먼저 확인·수정한 뒤 `tool/`에서 한 번 실행합니다. 관리자 인증은 OS의 인증 절차로만 진행하며 앱 자체를 root로 실행하지 않습니다.

```bash
sudo install -o root -g root -m 0644 linux/apparmor/arrow-studio /etc/apparmor.d/arrow-studio
sudo apparmor_parser --replace --skip-cache /etc/apparmor.d/arrow-studio
```

에이전트의 별도 보안 격리 내부에서는 추가 제한이 남을 수 있으므로 실제 호스트의 일반 터미널에서 실행합니다. 이전 개발 우회용 `start:local-unsandboxed`는 OS 샌드박스를 끄므로 현재 컴퓨터에서는 사용하지 않습니다. 기본 실행에서 보안 옵션을 자동으로 완화하지 않습니다. 권한 분리와 IPC 경계는 [Electron 공식 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)을 기준으로 구성했습니다.

## 먼저 사용해 볼 것

화면은 보드 중심의 밀집 배치로 조정했습니다. 창 높이에 맞춰 보드가 남은 공간을 채우며, 스테이지 목록과 우측 인스펙터는 각각 스크롤됩니다. 후보·버전은 보드 아래의 ‘후보와 저장 이력’을 펼쳐 확인합니다. 최신 화면은 [작업 화면](../docs/design/arrow-editor-editing-workspace.png), [환경설정](../docs/design/arrow-editor-editing-preferences.png)을 참고하세요. 같은 스테이지를 다시 눌러도 현재 후보·미저장 작업·선택이 유지됩니다.

보드 상단 **자동 배치**를 누르면 오른쪽에 상세 조절, 하단에 **자동 배치 · 영역별 설정표**가 열립니다. 하단의 후보·저장 이력과 설정표는 하나씩 펼쳐지며, 설정표 위쪽 손잡이를 끌어 높이를 조절합니다. 손잡이에 키보드 초점을 두고 위·아래 화살표로도 조절할 수 있습니다. 접힌 두 메뉴는 같은 줄에 배치해 보드 공간을 유지합니다. [자동 배치 화면](../docs/design/arrow-editor-placement-workspace.png)을 참고하세요.

설정표에는 전체 보드와 등록된 모든 영역의 일곱 항목이 표시됩니다. 행 이름·보드 영역·조절 대상 목록으로 대상을 고르며, 표와 상세 입력은 서로 동기화됩니다. 설정표 위쪽에는 **생성 대상**과 **랜덤 생성** 버튼이 있으며, 표를 스크롤해도 이 실행 줄은 계속 보입니다. 자동 배치 화면에서 보드 클릭은 영역 선택만 수행합니다. 랜덤 생성은 선택한 대상의 빈 칸에 1단계 배치를 만들고 남은 빈 칸을 2단계에서 채웁니다. 기본값은 1단계 30%, 채움률 70%, 길이 2~4칸입니다. 전체 보드의 유효성과 해결 가능성을 검사하며 실행 취소할 수 있습니다. 목표 칸 수와 실제 칸 수가 다르면 적용 여부를 선택합니다. 1단계에는 길이별 개수·비율, 굴곡과 두 종류의 막힘 목표를, 2단계에는 채움률과 균일도를 적용합니다. 목표 미달은 실제값과 함께 표시하며 자동 재시도 모드에서는 적용하지 않습니다. 입력값은 작업을 바꾸거나 앱을 다시 실행하면 초기화됩니다.

우측 최상단에는 화살 수·점유율·관리 영역 수·빈 배치 칸·금지 칸·보드 크기를 표시합니다. 점유율은 **금지 칸을 제외한 보드 중 화살표가 차지한 고유 칸의 비율**입니다. 중복·범위 밖 칸은 중복 집계하지 않지만 초안을 고치거나 규칙 검증을 대신하지는 않습니다. 재생 중 개수는 남은 화살 기준이며 원본 수는 별도로 표시합니다.

보드의 격자·화살 크기는 주변 문구·경고·분석 패널·복제 결과와 무관하게 유지합니다. 창 크기를 바꿔도 자동으로 확대·축소하지 않습니다. 전체를 다시 보고 싶으면 보드 오른쪽 아래의 **화면 맞춤**을 누르며, 휠 확대·축소와 휠 버튼 드래그·Shift+드래그 이동은 그대로 사용할 수 있습니다.

오류·경고는 상단의 기존 고정 안내줄에서 요약해 표시하며 화면을 밀거나 창을 자동으로 열지 않습니다. **상세보기**를 눌러 전체 내용을 확인하고 Esc 또는 닫기로 상세 창을 닫을 수 있습니다. 안내줄의 **닫기**는 알림만 해제하며 맵·저장·실행 취소 이력은 바꾸지 않습니다.

맵 조건은 풀이 가능 수·원본 최장 선행 연결·선택 영역의 제거 가능 수를 세 줄로 요약합니다. ‘상세·영역 선택’에서 설명·목표 설정·조회 영역 선택을 확인하고 ‘이 영역을 보드에서 보기’로 돌아옵니다. 조회 영역 변경만으로 후보나 저장 이력이 새로 생기지는 않습니다. 목표는 여전히 저장용 설정이며 자동 생성 제약이나 관문 전후 효과 판정은 미구현입니다.

1. `검증 예제로 시작`을 눌러 독립 제작 라이브러리에 보드를 만듭니다. 기존 게임의 스테이지를 덮어쓰지 않습니다.
2. `기본 조작`에서 빈 칸을 **최소 2칸** 드래그하면 새 화살을 만듭니다. 시작 칸이 머리이고 방향은 첫 두 칸으로 결정합니다. 화살 좌클릭은 선택, 머리·꼬리 드래그는 자동 직각 연장, 직선 몸통 드래그는 전체 이동, 코너 드래그는 양쪽 간격 조절입니다. 어느 부분에서든 전체 이동하려면 우클릭 → `전체 이동`을 사용합니다. 우클릭 메뉴에서 전체/그룹 90° 회전, 꺾임 간격 조절, 끝점 연장도 선택합니다. 놓을 때 Godot로 검사하고 실패하면 원본을 유지하며 실행 취소/재실행을 지원합니다. 휠 버튼(가운데 버튼) 드래그 또는 Shift+좌측 드래그는 보드 이동, 휠은 포인터 중심 확대·축소, Esc는 현재 조작·검사·창 취소입니다.
3. `영역`으로 사각 범위를 그립니다. 선택 영역을 `영역 + / −`로 한 칸씩 다듬습니다. 영역끼리는 겹치지 않습니다.
4. `Godot 검증·분석`으로 실제 규칙 검사, 현재 제거 가능 수, 전체 선행 연결 깊이를 확인합니다. 수정하면 이전 분석은 지워집니다.
5. `저장`은 같은 후보에 버전을 추가하고, `새 후보로 저장`은 별도 후보를 만듭니다. 과거 버전을 불러와 저장하면 과거를 덮지 않고 새 버전이 됩니다.
6. `흐름 분석`에서 한 화살씩 실제 코어로 제거합니다. 재생은 편집·저장 원본을 변경하지 않습니다.

왼쪽 순번과 ID는 분리되어 있으며 순서 변경·새 스테이지 추가·복제·보관을 지원합니다. 보관한 항목은 보관함에서 다시 열고 보관 해제할 수 있습니다. 빈 초안이나 규칙 오류가 있는 중간 상태도 후보에 저장할 수 있지만, JSON 내보내기는 규칙과 클리어 가능성을 통과해야 합니다.

앱의 목록은 기존 게임 카탈로그와 아직 별개입니다. 이 라이브러리의 `STAGE-001`을 만들었다고 게임의 `STAGE-001`이 변경되지는 않습니다. 가져오기는 런타임 배치 JSON만 받으며 기존 schema v3 생성 설정의 가져오기는 아직 지원하지 않습니다.

기존 저장본에 1칸 화살이 있으면 경고하며 자동으로 늘리거나 삭제하지 않습니다. 삭제 후 2칸 이상으로 다시 그려야 제작 검증·내보내기를 통과합니다. 신규 예제는 모두 2칸 이상입니다. 전체 이동은 최단 직각 이동 경로를 한 칸씩 검사하며 장애물 자동 우회는 하지 않습니다. 회전·간격·연장은 최종 배치를 검사합니다. [조작 방법과 구현 범위](../docs/stage_editor_arrow_editing.md)를 참고하세요.

꺾임 간격 조절은 **꺾인 코너를 좌클릭 드래그**하면 바로 시작합니다. 좌우·위아래·대각선으로 양쪽 간격을 함께 조절하며, 몸체 그룹이 직각 연결을 유지하도록 따라 움직입니다. 머리는 고정되지 않으며 각 연결 구간은 최소 1격자를 유지합니다. 마우스를 올리면 해당 지점이 머리·꼬리·직선 몸통·코너 중 어디인지 강조하고 실행할 기능을 안내합니다. 우클릭은 기존 기능 메뉴만 엽니다.

머리·꼬리와 직접 연결된 구간에서는 코너를 해당 끝점 너머까지 끌면 반대편으로 이어집니다. 정확히 끝점과 겹치는 칸에서는 한 격자를 유지하며, 그보다 더 끌면 반대편으로 넘어갑니다. 머리 방향은 남은 첫 두 칸으로 결정하므로 머리 쪽 통과 때 반전되고 꼬리 쪽만 바꾸면 기존 머리 방향을 유지합니다. 반전 후에도 충돌·금지 칸·경계 검사는 유지합니다.

머리·꼬리 드래그는 바깥으로 늘리기뿐 아니라 **기존 몸체를 따라 안쪽으로 줄이기**도 지원합니다. 꺾인 구간도 따라 줄이며 최소 두 칸을 남깁니다. 드래그 중 되짚으면 복원하고, 줄인 끝에서 새 방향으로 연장할 수도 있습니다. 머리를 줄이면 남은 몸체에 맞춰 방향을 다시 정하며 Esc 취소·실행 취소/재실행을 지원합니다. 우클릭 메뉴에서도 `머리 연장·축소` / `꼬리 연장·축소`로 같은 기능을 선택합니다.

## 화살 복제

기본 조작에서 **Alt+화살 드래그** 또는 **우클릭 → 복제 후 이동**으로 모양·길이·방향을 그대로 복제합니다. 머리·꼬리·코너를 잡아도 전체 복제이며 원본은 움직이지 않습니다. 놓을 위치의 겹침·금지 칸·경계를 Godot로 검사하며 성공 시 새 ID를 가진 복제본을 선택합니다. 제작 역할·영역 정의는 자동 복제하지 않습니다. 원래 자리로 돌아와 놓거나 Esc로 취소하면 복제본 없이 모드가 종료되고 미저장 상태·이력도 바뀌지 않습니다. Shift+드래그 보드 이동이 Alt 복제보다 우선합니다.

## 저장과 복구

기본 저장 위치는 저장소의 `authoring/`입니다.

- `library.json`: 스테이지 순서, 후보, 변경 불가인 과거 버전, 보드·영역·역할·목표.
- `recovery.json`: 미저장 편집의 별도 복구본. 자동으로 후보·버전을 만들지 않습니다.
- `settings.json`: 이 컴퓨터의 글자 크기·Godot 경로·프로젝트 경로·시간 제한.
- 각 파일의 `.bak`: 직전 파일 백업. 기록이 많은 라이브러리는 별도 복사 백업도 권장합니다.

임시 파일을 완성한 뒤 교체하고, 저장 충돌·손상된 원본·기존 버전 수정은 거절합니다. 이 초기 로컬 데이터는 `.gitignore`에 포함되므로 Git만으로 백업되지 않습니다. 데이터는 폴더째 별도 보관해 주세요. 32MB 라이브러리 제한에 도달하면 자동으로 과거 이력을 삭제하지 않고 저장을 중단합니다.

미저장 스테이지 전환은 저장/변경 버리기/취소를 제공합니다. 앱을 닫을 때에는 계속 편집하거나 복구본을 남기고 닫을 수 있습니다. 종료 창 안에서 바로 후보 저장하는 동작은 아직 구현하지 않았습니다. 복구 창에서 Esc를 누르면 복구본을 보존하고 편집을 잠급니다. ‘복구 창 열기’에서 복구 또는 버리기를 명시적으로 선택해야 편집을 재개합니다.

## 아직 연결하지 않은 기능

- 기존 배치를 유지하는 부분·영역 자동 생성, 제약 기반 재시도.
- 압박 구간의 반복 빈도·커버리지, 관문 전후 효과 자동 평가, 복수 경로 분석.
- 스테이지별 목표 자동 조정, 전체 맵 비교 화면.
- 임의의 몸체 그룹 이동과 최단 직각 경로 자동 재연결. 제한된 그룹 회전·꺾임 간격 조절·끝점 연장은 구현했습니다.
- 확정안 지정과 게임 로딩·순서 반영, 기존 운영 데이터 이행, OS별 배포.

목표와 제작 역할은 현재 저장용 메타데이터입니다. 목표를 입력하거나 관문 역할을 지정했다고 그 효과를 검증·생성한 것으로 표시하지 않습니다. 초기 화면은 이 차이를 명시합니다.

## 검증

[개발 원칙](../DEVELOPMENT.md)과 [테스트 원칙](../docs/testing_principles.md)에 따라 변경한 기능과 직접 영향을 받는 부분을 골라 검사합니다. 모든 명령은 `tool/`에서 실행합니다.

| 명령 | 검사 범위 |
|---|---|
| `npm run build` | TypeScript 타입 검사·배포용 빌드 |
| `npm run smoke` | 앱 시작·Node 권한 격리만 확인 |
| `npm run smoke:placement` | 자동 배치 UI·영역 선택·입력 동기화·접기·높이 조절·원본 보존 |
| `npm run smoke:layout` | 창 크기별 화면 배치·인스펙터·영역 분석 창 |
| `npm run smoke:preferences` | 글자 크기·환경설정 저장·재시작 후 유지 |
| `npm run smoke:workflow` | 코어 검증·기본 그리기·후보/버전 저장·제거 재생 흐름 |
| `npm run smoke:editing` | 수동 편집·드래그·회전·복제·끝점·코너 조작·입력 취소 |
| `npm run smoke:all` | 위 화면 모듈 전체, 명시적으로 선택할 때만 실행 |

화면 검사 명령에는 빌드가 포함됩니다. 예를 들어 자동 배치 UI만 바꿨으면 `npm run smoke:placement`로 검사하고, 공통 화면 배치도 수정했다면 `smoke:layout`을 추가합니다. 다른 화면 검사를 준비 과정으로 실행하지 않습니다. 자동 배치 UI 검사는 임시 보드를 직접 준비하므로 수동 그리기·회전·저장 검사나 Godot 분석을 선행하지 않습니다.

단위 검사도 `test:geometry`, `test:regions`, `test:camera`, `test:metrics`, `test:settings`, `test:library`, `test:core`, `test:notice`, `test:smoke-runner`로 선택합니다. `npm test`는 단위 검사 전체입니다. 빌드 후 `npm exec -- electron . --smoke-test=placement,layout`처럼 필요한 화면 모듈만 묶어 실행할 수도 있습니다.

화면 검사는 전용 임시 폴더를 사용하며 실제 제작 데이터에는 테스트 보드를 추가하지 않습니다. 실행한 모듈과 소요 시간은 `EDITOR_SUITE_START`·`EDITOR_SUITE_DONE`, 결과·임시 폴더·스크린샷 위치는 `EDITOR_SMOKE` 로그에서 확인합니다. 선택 검사 결과를 전체 검사 결과로 표시하지 않습니다. Electron의 기존 샌드박스 설정은 유지합니다.

기본 파일 접근은 main 프로세스가 담당하고 preload는 정해진 작업만 노출합니다. 원격 페이지·새 창·권한 요청을 막고 사용자 문서는 코드로 실행하지 않습니다. Godot 규칙을 TypeScript에 복제하지 않습니다.

생성 후 보드 위의 **전체 / 1단계만 / 2단계만 / 기존 화살만** 토글로 단계를 따로 볼 수 있습니다. 전체에서는 기존 화살은 흰색, 1단계는 주황색, 2단계는 하늘색입니다. 단계 정보는 후보·복구본·실행 취소 기록에 함께 보존됩니다. 단계만 보는 동안은 배치를 관찰하며, 전체 보기에서 편집합니다. 이전에 생성한 자료에는 단계 기록이 없어 새로 생성한 결과부터 구분됩니다.

보드 위의 **전체 화살 지우기**는 보드의 모든 화살을 삭제하고, **선택 영역 화살 지우기**는 몸체 전체가 선택 영역 안에 포함된 화살만 삭제합니다. 영역 경계에 걸친 화살은 유지하며 영역과 금지 칸은 지우지 않습니다. 두 동작 모두 실행 취소·다시 실행할 수 있습니다.
