# 밸런싱 제어와 맵 분석

상태: 맵별 구성 조건을 보존하고 풀이 흐름에서 확인하는 방향까지 사용자와 확인 / 단위·판정·화면은 구체화 중. 최신 통합 기준은 [맵의 난이도 구성 조건](stage_editor_difficulty_profile.md)입니다.

관련 기준: [2단계 기획](stage_editor_design.md), [부분 생성의 양과 보존 기준](stage_editor_generation.md).

## 1. 사용자 요구사항

- 특정 영역을 골라 개수·퍼센트만큼 추가 생성할 수 있어야 합니다.
- 작업 방향에 따라 맞물림, 연쇄, 풀이 가능 개수 같은 제약을 설정하여 난이도를 조절합니다.
- 같은 항목을 현재 맵에서 측정하여 난이도를 수치로 파악할 수 있어야 합니다.
- 생성 조건과 실제 결과의 차이를 편집기에서 알아볼 수 있어야 합니다.
- ‘풀이 가능 개수’는 현재 시점에 바로 제거할 수 있는 화살표 수입니다. 서로 다른 전체 풀이 순서 수를 요구하는 의미가 아닙니다.

후보 A/B 같은 작업 분기와 퍼즐 안의 연쇄·선택지 구조를 구분해서 표현합니다. 후보를 분기해도 관련 생성 조건과 분석 근거를 함께 보존할 수 있도록 설계하는 방향을 제안합니다.

## 2. 생성 영역과 제약의 평가 범위

생성 영역은 새 화살표를 배치할 위치를 정합니다. 난이도 제약의 평가 범위는 어떤 화살표들의 관계와 선택지를 측정할지 정합니다. 영역 안에서 생성해도 밖의 화살표와 막힘 관계가 생길 수 있습니다.

다음 구분을 화면과 데이터에서 유지하는 방향을 제안합니다.

| 범위 | 확인할 내용 |
|---|---|
| 선택 영역 | 점유율, 배치 수, 영역에서 만들고 싶은 구조 |
| 기존·신규 사이 | 새로 생긴 막힘 관계, 기존 맵과의 연결, 연쇄의 변화 |
| 전체 맵 | 모든 화살표를 포함한 클리어 가능성, 전체 연쇄 깊이와 선택지 변화 |

사용자는 영역별 목표와 전체 맵 목표를 나누는 방향에 관심이 있으나 부분 작업에서 관리하는 방식의 구체적 제안을 요청했습니다. 아래는 아직 최종 확정하지 않은 관리안입니다.

### 관리안: 전체 목표를 기본으로 두고 영역 제약은 필요할 때 추가

1. 생성 영역은 배치 위치만 제한합니다. 개수는 영역에 추가하는 실제 화살표 수, 점유율은 영역 안의 사용 가능한 칸 기준입니다.
2. 전체 맵의 완성 목표를 기본 밸런싱 설정으로 둡니다. 제거 가능한 수·비율, 연쇄 깊이 등의 목표와 현재 값을 비교합니다.
3. 부분 작업 중에는 완성 목표와의 차이를 표시합니다. 완성 목표를 아직 못 채웠다는 이유만으로 모든 중간 작업의 저장·진행을 막지 않습니다.
4. 이번 추가 생성에서 반드시 지키려는 조건은 별도로 지정합니다. 기존 배치 보존·영역 제한·추가량과, 명시한 관계 조건의 충족 여부를 결과에서 확인합니다.
5. 특정 영역을 의도적으로 다르게 설계하고 싶을 때만 ‘영역별 제약 추가’를 엽니다. 해당 영역의 값도 전체 보드 상태를 기준으로 판정합니다.
6. 분석 화면에는 선택 영역과 전체 맵을 나란히 표시합니다. 영역별 제약을 켜지 않아도 영역의 수치를 확인할 수 있습니다.

전체 목표는 추가 생성 결과를 목표에 가까워지도록 평가하는 기준으로도 사용하는 방향을 제안합니다. 이번 작업에서도 꼭 지키려는 값은 이번 추가 생성의 제약으로 지정할 수 있게 구체화합니다. 완성 목표와 중간 작업의 필수 조건을 혼동하지 않습니다.

제거 가능 여부는 모든 화살표를 남겨둔 실제 보드에서 판정합니다. 영역 밖 화살표가 길을 막으면 그 화살표는 선택 영역 집계에서도 막힌 상태입니다.

영역의 화살표 수는 **머리가 영역 안에 있는 화살표**를 한 개로 집계하는 기준을 제안합니다. 영역에 걸친 몸체를 잘라 별개 화살표처럼 세지 않습니다. 점유율은 해당 영역 안의 몸체 칸 수를 세므로 개수 집계와 기준이 다릅니다.

예를 들어 전체 12개 중 제거 가능 3개·막힘 9개이고, 영역 R1 소속 4개 중 제거 가능 1개·막힘 3개라면 이를 함께 표시합니다. 다른 영역에 추가한 화살표가 R1의 길을 막으면 R1 수치도 다시 계산합니다. 이 예시는 설명용이며 현재 목업의 실제 분석 결과가 아닙니다.

영역과 관련된 연쇄는 전체 의존 관계에서 해당 영역 화살표까지 이어지는 선행 관계를 사용하는 방향을 제안합니다. 영역 경계에서 관계를 잘라 계산하지 않습니다. 영역 내부 관계와 영역을 드나드는 관계를 별도로 표시하며, 세부 집계·목표 계약은 후속 설계에서 고정합니다.

점유율은 선택 범위의 배치 가능한 칸을 분모로 삼고, 개수는 실제 추가 화살표 수로 제안합니다. 제어 지표가 비율이면 어떤 화살표 집합을 분모로 사용했는지도 함께 표시합니다.

## 3. 처음 구체화할 제약과 지표

| 항목 | 사용자가 조절하려는 의미 | 결과에서 확인할 수치 |
|---|---|---|
| 생성량 | 영역을 얼마나 채울지 | 실제 추가 수, 점유 칸, 영역·전체 점유율 |
| 맞물림 | 어떤 화살표가 다른 화살표의 길을 막을지 | 차단 관계 수, 기존·신규 사이의 관계, 한 화살표가 막는 수 |
| 연쇄 | 먼저 제거해야 할 관계가 얼마나 이어질지 | 연쇄 깊이, 주요 선행 제거 관계 |
| 현재 제거 가능한 수 | 현재 보드에서 바로 뺄 수 있는 화살표가 몇 개인지 | 제거 가능 수·비율, 막힌 수·비율 |
| 풀이 진행 중 선택지 | 제거를 진행하면 선택지가 어떻게 변하는지 | 단계별 선택지, 평균 선택지 |
| 강제 선택과 연속 해제 | 한 수만 가능한 구간과 한 번에 쉽게 열리는 정도 | 강제 선택 비율·연속 구간, 제거 후 새로 열리는 수 |

같은 보드 상태와 같은 화살표 집합에서 `막힌 수 = 전체 수 - 제거 가능한 수`입니다. 두 수를 함께 표시하되, 생성 목표를 입력할 때는 제거 가능한 수 또는 막힌 수 중 하나를 기준으로 선택하는 방식을 제안합니다. 유효성·판정 오류가 있으면 오류로 표시하며 계산하지 못한 대상을 임의로 막힌 화살표에 포함하지 않습니다.

서로 다른 전체 풀이 순서 수는 이번 사용자가 설명한 ‘풀이 가능 개수’의 범위에 포함하지 않습니다. 현재 보드에서의 값과 풀이 재생 중 남은 보드에서의 값은 각각 해당 상태를 기준으로 계산합니다.

제거 가능한 선택지를 제어할 경우 초기 값과 진행 중 값을 구분해야 합니다. 예를 들어 마지막 화살표 하나가 남았을 때도 항상 선택지 3~5개를 요구할 수는 없습니다. 진행 중 제약은 적용 구간·통계·남은 화살표 수와의 관계를 별도로 설계합니다.

연쇄 깊이가 길거나 강제 선택이 많다는 사실만으로 체감 난이도가 높다고 단정하지 않습니다. 하나를 제거한 뒤 다수가 쉽게 풀리는 구조도 함께 측정하는 방향으로 제안합니다.

## 4. 생성 조건과 실제 결과의 표시

- 설정 화면에는 원하는 목표 범위·단위·평가 범위를 표시합니다.
- 전체 완성 목표, 이번 추가 생성의 제약, 선택적으로 추가한 영역별 제약을 구분해 표시합니다. 모두 동일한 시점에 강제하는 한 묶음으로 만들지 않습니다.
- 결과 화면에는 실제 측정값·목표 충족 여부·기존 맵 대비 변화를 표시합니다.
- 생성할 때 설정한 값과, 현재 보드에서 측정한 값을 같은 값으로 취급하지 않습니다.
- 필수 조건과 권장 목표를 구분하는 방식을 제안하며, 항목별 기본 강도는 사용자와 후속 설계에서 정합니다.
- 필수 제약 미달 결과를 성공으로 표시하거나, 목표를 자동으로 완화하여 채택하지 않습니다.
- 미달 결과를 참고하거나 수동으로 적용할 수 있는 범위는 초안 저장·정식 확정 정책과 함께 정합니다.
- 수정 후 이전 분석은 현재 보드와 다른 결과임을 표시하고 다시 분석할 수 있게 합니다.

후보의 각 저장 이력에 보드 상태와 관련 생성 조건, 분석 대상 버전, 측정 모델 버전을 연결하는 방향으로 제안합니다. 생성·분석 실행만으로 저장 이력을 자동 추가하지 않습니다.

## 5. 난이도 수치화의 단계

우선 설명 가능한 지표 묶음으로 현재 맵을 수치화합니다. 화살표 수·점유율·연쇄 깊이·선택지 변화 등을 나란히 보여 어떤 구조 때문에 결과가 달라졌는지 확인할 수 있게 합니다.

사용자는 통합 난이도는 추정치일 뿐이며, 핵심은 요소별 목표·빈도·커버리지를 맵 속성으로 관리하는 것이라고 정리했습니다. 따라서 통합 점수·등급을 기본 설계로 두지 않으며 임의의 0~100 점수를 실제 난이도로 표시하지 않습니다. 현재 상태만이 아니라 주요 전환점의 영역 개방·선택지·연쇄 반복을 확인합니다.

선택지·강제 선택 지표 중 일부는 대표 풀이 한 경로에서 얻는 값입니다. 그 경로의 값과 모든 풀이 순서를 조사한 통계를 구분하고 측정 방법을 함께 기록합니다.

## 6. 현행 코드와의 차이

| 지표·기능 | 현재 코드에서 확인한 상태 | 이후 필요한 일 |
|---|---|---|
| 전체 연쇄 깊이 | 계산하고 생성 목표로 비교 | 기존 배치 보존·영역 생성에서도 의미 유지 |
| 초기 제거 가능 수·비율 | 둘 다 계산, 생성 목표는 비율 사용 | 개수 조건과 적용 범위 구체화 |
| 단계별·평균 선택지, 강제 선택 비율 | 대표 풀이 한 경로에서 계산 | 진행 구간 제약과 평가 범위 확장 |
| 강제 선택 비율의 목표 | 설정 데이터는 있으나 현재 후보 채택·점수에서 강제하지 않음 | 측정만 할지 실제 제어할지 명시 |
| 전체 차단 관계 | 방해·종속 관계와 간선 수 계산 | 영역 안·밖, 기존·신규 관계별 집계 |
| 생성 목표 미달 | 목표에 가까운 해결 가능한 후보를 반환할 수 있음 | 엄격한 제약과 권장 목표를 구분해 결과 계약 정리 |
| 영역별 난이도 목표 | 현재 별도 계약 없음 | 전체 판정을 유지한 지역 집계·제어 설계 |
| 맵별 구성 조건·빈도·커버리지 | 현재 별도 계약 없음 | 통합 점수 없이 요소별 저장·생성·분석 계약 설계 |

기존 `MyRequest/`의 난이도 조사 문서는 아이디어 근거로 사용합니다. 고정 9×9 보드나 강제 선택 비율의 채택 조건처럼 현재 코드와 달라진 설명은 그대로 구현 사실로 사용하지 않습니다.

## 7. 단계별 반영

화면 관리안: [전체 목표와 선택적 영역 제약 목업 v0.6](wireframes/07-balancing-scope-v06.png) / [SVG 원본](wireframes/07-balancing-scope-v06.svg).

추가 논의: 사용자가 선택지를 줄이는 화살표, 연쇄를 잇는 화살표, 영역을 여는 화살표를 정의해 작업 방향별로 배치하는 방식을 제안했습니다. [화살표 배치 역할 초안](stage_editor_arrow_roles.md)에서 제작 의도와 검증된 효과를 구분하며 구체화합니다.

- 2단계: 제거 가능한 수의 뜻은 확인했으며, 생성 영역과 평가 범위의 관리안·목표 충족 정책·화면 흐름을 계속 구체화합니다.
- 4단계: 기존 코어를 재사용하며 부분·영역 생성, 제약 제어, 분석 집계·응답을 확장하고 검증합니다.
- 5단계: 영역 선택·생성 조건·목표 대비 결과·후보별 이력을 실제 편집 흐름에 연결합니다.

인수 기준에는 영역 밖 배치·기존 화살표 변경 방지, 전체 보드 풀이 판정, 제약별 목표와 실측의 일치, 목표 미달 명시, 대표 경로 통계의 재현성, 분석한 보드와 편집 중 보드의 버전 구분을 포함합니다.
