# 첫 실제 구현 — 확실한 기능부터

상태: 초기 데스크톱 앱 구현 / 전체 6단계 완료가 아닙니다.

최신 개선: [기본 마우스 조작·우클릭 변형·Shift 이동·휠 확대·Esc 취소](stage_editor_arrow_editing.md). 방향·좌표 직접 수정은 제거했고, 아래 최초 구현 기록과 구분합니다. [최신 변형 화면](design/arrow-editor-interactions.png), [우클릭 메뉴](design/arrow-editor-context-menu.png), [환경설정](design/arrow-editor-editing-preferences.png).

사용자는 남은 권장안을 우선 구현 기준으로 채택하고, 모호한 내용은 후속 개발로 남겨도 되므로 확실한 기능부터 구체화하도록 요청했습니다. 이에 미정 계산식의 결론을 기다리지 않고 기본 앱→편집→저장→실제 코어 분석의 작은 사용 흐름을 우선 연결했습니다. 기존 단계 번호는 유지하지만 이번 초기 실물은 3단계 기반과 4·5단계 일부를 함께 확인하는 첫 구현입니다.

## 구현한 흐름

- 독립 Electron 앱, React + TypeScript 화면, Discord 외관.
- 실제 스테이지 목록·순서·추가·현재 보드 복제·보관/해제. 기존 게임 목록과는 아직 별개입니다.
- 머리부터 몸체 드래그, 점·방향·역할 수정, 삭제, 실행 취소/재실행.
- 관리 영역 그리기·칸 추가/제외·이름, 영역 중복 방지, 금지 칸 편집.
- 같은 후보의 버전 저장, 명시적인 새 후보 분기, 과거 버전에서 재개.
- 자동 복구본, 저장 충돌 방지, 직전 파일 백업, 기존 버전 변경 방지.
- 공용 코어의 `analyze_stage` 추가: 유효성, 방해 관계, 제거 가능 ID, 기존 선행 깊이, 대표 경로·클리어 가능성.
- 원본을 보존하는 실제 제거 재생, 런타임 배치 JSON 가져오기·검증 후 내보내기.

## 미구현·보류

부분 생성·반복 압박 제어·복수 경로 평가·스테이지별 자동 조정·확정안·게임 반영은 미구현입니다. 역할·목표 입력은 저장하되 자동으로 생성·검증했다고 표시하지 않습니다. 기존 무작위 모드와 Sheets·게임 데이터는 변경하지 않았습니다. 별도 맵 비교 화면은 후속이며 보드 자체의 확대·이동은 구현했습니다.

종료 시 ‘계속 편집 / 복구본을 남기고 닫기’까지 구현했으며 종료 창에서 직접 후보 저장은 아직 없습니다. 정식 제작 데이터의 이행 계약과 기존 진행 데이터 호환은 다음 단계에서 다룹니다. 로컬 작업 데이터는 `authoring/`에 두며 Git에서 제외됩니다.

## 보드 중심 화면 조정 — 2026-10-20

사용자 피드백에 따라 Discord 색상은 유지하고 버튼·제목·여백·모서리를 편집 도구에 맞게 간결하게 조정했습니다. 화면 높이에 따라 보드를 360px로 제한하던 스타일을 없애고 남은 작업 공간을 사용합니다. 스테이지 목록과 인스펙터는 독립적으로 스크롤하며 후보·버전은 기본 접힘으로 바꿨습니다.

우측 최상단에 현재 스테이지 정보와 화살 수·배치 점유율·관리 영역 수·빈 배치 칸·금지 칸·보드 크기를 모았습니다. 맵 조건은 세 줄 조회로 줄였으며 상세 설명·목표 설정·영역 선택은 별도 창으로 이동했습니다. 조회 영역 변경은 보드 강조에 반영되며 후보·버전을 만들거나 저장 데이터를 바꾸지 않습니다. 점유율은 금지 칸을 제외한 보드의 고유 점유 칸 비율이며 게임 규칙 판정은 여전히 Godot만 수행합니다.

새 화면: [작업 화면](design/arrow-editor-compact-workspace.png), [맵 조건 상세](design/arrow-editor-compact-intent.png). 기존 [첫 구현 화면](design/arrow-editor-first-build.png)은 비교용으로 보존합니다.

## 실행 환경 주의

초기 검증 때는 Ubuntu의 OS 샌드박스 제약으로 임시 우회가 필요했으나, 2026-10-20 사용자 요청으로 에디터 실행 파일 한 곳에만 AppArmor의 사용자 네임스페이스 허용 프로필을 설치·활성화했습니다. OS 전체 보안 제한과 앱 기본 보안은 유지했습니다. 이후 일반 `npm run smoke`가 우회 없이 통과했고 실제 renderer의 `NoNewPrivs: 1`, `Seccomp: 2`를 확인했습니다. 이제 이 컴퓨터에서는 일반 `npm start`를 사용합니다. 프로젝트 이동·다른 PC의 설정은 [실행 안내](../tool/README.md)를 참고합니다. 이 결과만으로 3단계의 나머지 인수 조건이나 다른 OS 검증까지 완료한 것으로 처리하지 않습니다.

실행 안내: [tool/README.md](../tool/README.md). 현재 UI·저장 파일은 목업이 아닌 실제 동작이며, 미연결 항목은 별도로 표시합니다.

## 검증 결과

- TypeScript 검사와 Vite 빌드 통과, 소스 포맷 검사 통과.
- Node 테스트 11개 통과: 저장·과거 버전 보존·충돌·손상 파일·복구본·실제 Godot 호출·취소·시간 제한·잘못된 응답·중복/금지/범위 밖 칸 집계·빈 보드/배치 가능 칸이 없는 보드.
- Electron 통합 테스트 통과: 실제 마우스의 머리 우선 화살표·35칸 영역 생성, 실행 취소/재실행, 같은 후보 v1→v2, 명시적 새 후보, 공용 규칙 제거 3회, renderer의 Node 접근 차단.
- 화면 조정 후 통합 테스트에서 1100×740·1280×800·1680×1080·1920×1080을 확인했습니다. 페이지 넘침 없이 우측 상단 인스펙터와 세 조건 수치가 보이며 창 크기 변경 후 실제 화살 선택 좌표도 일치합니다. 1680×1080에서 보드 실제 표시 높이는 약 658 CSS px입니다. 상세 창의 조회 영역 전환과 저장 원본 보존도 검증했습니다.
- Godot 15개 스위트 통과(필수 4개·기존 bridge/CLI·새 분석 포함). 대형 생성 관련 기존 실패 2개는 생성기를 변경하지 않아 이번에 재실행하지 않았으며 미해결로 유지합니다.
- 병렬 검사에서는 기존 애니메이션 타이밍 단언이 한 번 실패해 순차 재실행으로 통과를 확인했습니다. 분석 회귀는 전체 카탈로그의 대형 생성 때문에 일괄 실행기의 45초 제한에 걸렸고, 별도 실행에서 완료·통과를 확인했습니다. 테스트 단언·생성 목표·게임 규칙은 완화하지 않았습니다.

실제 화면: [첫 앱 스크린샷](design/arrow-editor-first-build.png). 이 화면은 정적 목업이 아니라 통합 테스트에서 작성·저장한 보드를 실행한 결과입니다. 현재 Ubuntu의 OS 샌드박스 실행은 검증했으며 Windows/macOS 실기 검증은 아직 완료하지 않았습니다.
