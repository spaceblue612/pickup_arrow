# 화살표의 배치 역할 — 밸런싱 초안

상태: 역할과 관계를 맵에 보존하고 풀이 흐름으로 검증하는 방향 확인 / 역할별 수치·생성 조작은 미확정. 최신 통합 기준은 [맵의 난이도 구성 조건](stage_editor_difficulty_profile.md)입니다.

관련 문서: [맵 밸런싱과 분석](stage_editor_balancing.md), [부분 생성](stage_editor_generation.md).

## 1. 개념

선택 영역에 화살표를 추가할 때 생성량과 함께 원하는 역할을 지정하는 방향을 제안합니다. 현재 게임의 좌표·경로·제거 규칙으로 실제 효과를 검증합니다. 역할 이름만으로 다른 화살표를 자동 제거하거나 영역을 강제로 여는 새 게임 규칙을 도입하는 의미는 아닙니다.

후보 A/B로 나누는 작업 방향별로 다른 역할 계획을 시도하고, 후보의 저장 이력에 설정과 분석 근거를 연결할 수 있게 설계합니다.

## 2. 먼저 정의할 세 역할

| 역할 이름 제안 | 배치 의도 | 확인할 효과 |
|---|---|---|
| 선택지 억제 | 기존에 제거 가능하던 여러 화살표의 길을 막아 찾을 수 있는 수를 줄임 | 배치 전후의 제거 가능 수, 새로 막힌 기존 화살표 수, 전체 클리어 가능성 |
| 연쇄 연결 | 특정 화살표 제거 후 다음 화살표를 제거하는 관계가 이어지게 함 | 선행 관계의 깊이, 합법적인 제거 순서, 단계별 새로 열리는 수 |
| 영역 관문 | 특정 화살표가 다른 영역의 진행을 제한하고, 제거하면 해당 영역의 선택지가 열리게 함 | 대상 영역의 제거 가능 수 변화, 기존·신규 및 영역 간 관계 |

역할은 중복될 수 있습니다. 하나의 화살표가 선택지를 억제하면서 동시에 영역 관문이 될 수 있으므로 역할 개수를 단순 합산하여 전체 화살표 수로 계산하지 않습니다.

연쇄는 먼저 제거해야 하는 관계가 이어지는 뜻입니다. 한 번 누르면 여러 화살표가 자동으로 사라지는 기능을 포함하지 않습니다.

## 3. 의도와 검증 결과

- ‘이 화살표를 관문으로 쓰고 싶다’는 제작 의도와 실제로 그 영역을 여는 효과가 확인되었는지를 구분합니다.
- 배치된 역할 화살표의 수만으로 난이도를 계산하지 않습니다.
- 특정 화살표가 직접 막는 화살표 수와, 그 화살표를 제거한 뒤 실제로 새로 제거 가능해지는 수를 구분합니다. 다른 방해물이 남으면 직접 막았던 화살표도 바로 열리지 않을 수 있습니다.
- 제거 전후 효과는 그 화살표를 합법적으로 제거할 수 있는 상태에서 검증합니다. 아직 제거할 수 없는 화살표를 가정으로 지운 계산은 실제 플레이 효과와 구분합니다.
- 역할이 풀이 도중에 드러나는 경우 해당 보드·풀이 단계·제거 순서를 근거로 기록합니다.
- 보드가 바뀌면 역할 효과도 달라질 수 있으므로 이전 분석은 해당 저장 버전과 연결합니다.

선택지 억제의 배치 효과는 기존 화살표 중 새로 막힌 수와 전체 제거 가능 수의 변화를 함께 확인하는 방향으로 제안합니다. 새 화살표 자체가 제거 가능해지는 경우가 있으므로 둘을 같은 수치로 보지 않습니다.

영역 관문의 예시는 ‘R1에 새 관문을 배치하여 R2의 진행을 제한하고, 관문을 합법적으로 제거하면 R2에서 적어도 3개가 새로 제거 가능해짐’입니다. 실제 배치 위치와 효과가 나타나는 영역은 다를 수 있습니다.

## 4. 생성 화면의 제안

이번 추가 생성에 대해 생성 영역, 추가량, 원하는 역할과 효과 범위, 대상 영역을 지정하는 구조를 검토합니다.

- 생성 영역·추가량은 기존에 논의한 개수·점유율 기준을 사용합니다.
- 역할별 수·효과는 해당 추가량 안에서 달성할 목표로 둡니다.
- 기존 화살표를 보존하며, 목표를 맞추기 위해 기존 위치·방향·몸체를 임의 변경하지 않습니다.
- 한 조건을 달성하려다 제거 가능한 화살표가 없어지거나 순환이 생기지 않는지 전체 보드로 확인합니다.
- 역할 목표가 공간·현재 배치와 양립하지 않으면 달성하지 못한 이유를 표시하고 자동으로 역할을 충족했다고 간주하지 않습니다.

역할을 처음에 배치하고 나머지를 채울지, 기존 부분 생성 결과에서 역할을 측정하여 재시도할지는 구현 비교가 필요합니다. 현재 2단계에서 특정 생성 알고리즘으로 확정하지 않습니다.

## 5. 난이도와의 관계

선택지를 줄이는 역할은 첫 수 찾기를 어렵게 할 수 있습니다. 반대로 관문 하나를 찾은 뒤 많은 화살표가 쉽게 풀리면 이후 부담은 줄어들 수 있습니다. 연쇄가 길어도 다음 수가 매번 하나뿐이면 풀이가 명확해질 수 있습니다.

따라서 역할별 효과와 함께 선택지 변화, 새로 열리는 화살표 수, 강제 선택 구간, 영역 사이의 연결을 측정합니다. 통합 점수를 기본 목표로 두지 않고, 맵별로 목표 수준·빈도·커버리지를 관리하는 최신 방향을 따릅니다. 연쇄 깊이와 압박 구간이 다시 나타나는 빈도는 구분합니다.

## 6. 기존 설계·구현과의 관계

기존 브레인스토밍에는 CHAIN, FAN_OUT, FAN_IN, REGION_GATE 등의 모듈 아이디어가 있습니다. 이번 제안을 구체화할 때 참고하되 이미 구현된 역할 기능으로 취급하지 않습니다.

현재 생성기에는 의존 관계의 뼈대를 구성하는 코드가 있고, 분석기는 방해·종속 관계와 대표 풀이 순서를 계산합니다. 이를 재사용할 수 있지만 역할별 생성 목표·배치 효과·영역 관문 검증은 추가 설계와 구현이 필요합니다.

역할 중심 제어의 구체적인 첫 버전 범위는 2단계에서 토론한 뒤 확정하고, 코어 제어·검증은 4단계, 편집기 조작과 시각화는 5단계에 연결하는 방향으로 검토합니다.
