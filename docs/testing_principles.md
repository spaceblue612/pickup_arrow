# 테스트 원칙

[개발 원칙](../DEVELOPMENT.md)의 공통 테스트 기준입니다. 사람과 에이전트 모두 같은 기준으로 검사 범위를 선택합니다.

## 범위 선택

1. 수정한 기능과 그 기능을 직접 사용하는 부분을 확인합니다.
2. 빌드·타입 검사와 관련 단위 테스트부터 실행합니다.
3. 화면·입력 흐름이 바뀌었으면 해당 기능의 화면 테스트만 추가합니다.
4. 공통 코드 변경이나 검사 실패로 영향이 더 넓다고 확인되면 그 범위까지 확대합니다.

전체 검사는 배포 전, 여러 기능에 걸친 공통 규칙 변경, 영향 범위가 넓다고 확인된 통합 변경에 사용합니다. 시간이 남았다는 이유나 기존 실행 명령에 묶여 있다는 이유만으로 전체 검사를 실행하지 않습니다. 반대로 필요한 검사를 소요 시간만으로 생략하지도 않습니다.

## 테스트 모듈 구성

- 기능별로 독립 실행할 수 있게 작성합니다. 한 테스트를 실행하기 위해 다른 기능의 테스트를 먼저 통과해야 하는 구조를 만들지 않습니다.
- 필요한 시작 데이터는 전용 임시 라이브러리에 직접 준비합니다. 설정 UI 검사 준비를 위해 화살 그리기·회전·저장 과정을 재생하지 않습니다.
- 화면 조작·대기 같은 공통 도구와 기능별 검증을 분리합니다. 특정 모듈 선택 시 다른 모듈은 실행하지 않습니다.
- 실제 규칙을 확인할 필요가 있는 테스트에서는 공용 코어를 사용합니다. 순수 UI 검사에 불필요한 Godot 분석·생성을 추가하지 않습니다.
- 테스트는 실제 제작 데이터와 분리합니다. 테스트 간에는 후보·선택·복구본 같은 상태에 의존하지 않도록 시작 상태를 준비합니다.
- 회귀 검사는 사용자 동작과 관찰 가능한 결과를 확인합니다. 구현을 그대로 반복하는 검사나 같은 경로를 중복 실행하는 검사를 늘리지 않습니다.

## 에디터 검사 선택표

아래 명령은 `tool/`에서 실행합니다. 화면 검사 명령에는 빌드·타입 검사가 포함됩니다.

| 변경 범위 | 먼저 선택할 검사 |
|---|---|
| 자동 배치 설정 UI·대상 선택·접이식 설정표 | `npm run smoke:placement` |
| 공통 화면 배치·인스펙터·반응형 크기 | `npm run smoke:layout`와 영향을 받는 UI 모듈 |
| 글자 크기·환경설정 | `npm run test:settings`, `npm run smoke:preferences` |
| 화살 모양 계산 | `npm run test:geometry`; 입력 동작도 바뀌면 `smoke:editing` 추가 |
| 영역 이동·경계 계산 | `npm run test:regions`; 관련 화면 검사 추가 |
| 보드 확대·축소·좌표 변환 | `npm run test:camera`; 관련 입력 또는 배치 검사 추가 |
| 점유율 등 보드 수치 계산 | `npm run test:metrics` |
| 알림 표시 | `npm run test:notice`; 화면 배치도 바뀌면 `smoke:layout` 추가 |
| 후보·버전·복구 저장 | `npm run test:library`, `npm run smoke:workflow` |
| Godot 연결·요청 처리 | `npm run test:core`, `npm run smoke:workflow` |
| 수동 편집·드래그·회전·복제 | `npm run smoke:editing` |
| 화면 테스트 선택기·준비 데이터 | `npm run test:smoke-runner`와 변경한 실행 경로의 대표 모듈 |

`npm run smoke`는 앱 시작과 권한 격리만 확인하는 짧은 검사입니다. 기능 검사나 전체 검사를 통과했다는 의미로 사용하지 않습니다. 단위 검사 전체는 `npm test`, 화면 검사 전체는 **명시적으로** `npm run smoke:all`로 실행합니다.

빌드 후 여러 모듈만 한 번에 선택할 수도 있습니다.

```bash
npm run build
npm exec -- electron . --smoke-test=placement,layout
```

잘못된 모듈 이름은 오류로 종료하며 전체 검사로 대체하지 않습니다. 모듈별 시작·완료와 소요 시간은 `EDITOR_SUITE_START`, `EDITOR_SUITE_DONE`에, 실제 실행한 목록과 결과는 `EDITOR_SMOKE`에 남습니다.

## 게임 코어 검사

에디터 UI만 바꾼 경우 게임플레이 전체 검사를 자동으로 추가하지 않습니다. 게임플레이를 변경한 경우에는 저장소의 필수 회귀 검사인 `test_gameplay_core.gd`, `test_stage_catalog.gd`, `test_playable_flow.gd`, `test_arrow_placement.gd`를 유지합니다. 그 밖의 기능 검사는 변경한 규칙과 상태 전환에 맞춰 선택합니다.

## 결과 보고

실행한 모듈, 성공·실패, 필요한 경우 소요 시간만 간결하게 보고합니다. 선택 검사만 수행한 결과를 전체 검증 완료로 표현하지 않습니다. 실패하면 먼저 해당 모듈을 재현하고, 관련 변경이 없는 검사를 반복하지 않습니다.
