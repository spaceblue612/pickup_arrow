# 맵의 난이도 구성 조건 — 통합 정리

상태: [A 항목의 핵심 정의](stage_editor_decisions.md#a-맵-조건의-의미)는 사용자 확인 후 기획 기준으로 채택 / 실제 목표값·상세 판정식과 B·C 조작·운영은 구체화 중. 현재는 전체 6단계 중 2단계이며 생성·분석 기능을 구현한 문서가 아닙니다.

## 1. 확인한 방향

난이도를 하나의 확정 점수로 합치지 않습니다. 맵별로 제작자가 원하는 구조를 저장하고 실제 풀이 흐름에서 확인합니다.

핵심 요소는 풀이 가능 개수, 연쇄 단계, 영역 개방 정도입니다. 각 요소에 목표 수준, 등장 빈도, 적용 범위·커버리지를 지정하고 이후 요소도 같은 방식으로 확장합니다. 직접 설정과 스테이지별 자동 조정이 필요하며, 대화에 나온 50%, 45%, 5% 등은 설명용 예시이지 고정된 값이 아닙니다.

여기서 연쇄의 반복은 이미 열린 화살표가 다시 막힌다는 뜻이 아닙니다. 한 구간을 푼 뒤 다른 구간의 관문·선행 관계를 만나거나, 남은 제거 가능 수가 적어지는 압박 구간이 다시 등장하는 구조입니다.

생성 자유도가 일부 제한되더라도 이런 제어를 제공하는 방향입니다. 런타임 실시간 생성보다 제작 도구에서 충분히 탐색·검증하는 방식을 사용하되, 시간 확보만으로 모든 조건을 만족한다고 보장하지 않습니다.

## 2. 복잡도를 줄이는 세 구분

| 구분 | 보존·확인할 내용 | 화면에서의 위치 제안 |
|---|---|---|
| 맵에 저장할 조건 | 영역 정의, 화살표의 역할·대상 영역, 요소별 목표·빈도·커버리지, 직접/자동 설정 | 작업 화면에서 요약 상시 조회, 상세 설정은 팝업 |
| 현재 상태 | 지금 남은 수, 제거 가능 수, 막힌 수, 선택 화살표의 방해 관계 | 작업 화면에서 간단히 표시 |
| 풀이 흐름의 결과 | 맵 전체 선행 관계, 주요 전환점, 영역별 막힘·개방 변화, 압박 반복의 측정 근거 | 분석 화면에서 확인 |

맵의 원본 배치·설계 조건과 해당 버전에서 계산한 분석 결과는 구분합니다. 제작 중 수정한 순서는 게임 안의 연쇄를 증명하지 않습니다. 실제 합법 제거 순서와 그 시점의 보드가 분석 근거입니다.

제거한 화살표도 원본 관계에서는 유지하고 현재 재생 상태에서만 제거 표시합니다. 맵을 수정하면 이전 분석과 현재 작업의 불일치를 표시하며, 이전 저장 버전의 결과를 현재 결과로 재사용하지 않습니다.

## 3. 공통 설정 틀과 요소별 차이

| 항목 | 확인한 기준 | 후속 구체화 |
|---|---|---|
| 목표 수준 | 제거 가능 수, 선행 연결 깊이, 필요한 선행 수, 관문 후 개방량을 구분 | 실제 기본 범위·입력 제한·복합 사건의 상세 판정 |
| 등장 빈도 | 최초 화살 수 대비 제거 진행률 간격을 기본으로 하며 확률은 별도 | 압박 임계값·적용 구간·간격 허용 오차의 기본값 |
| 적용 범위·커버리지 | 원본 대상 중 역할에 의존하는 화살 수·비율, 중복 제외, 지속 구간은 별도 | 대상 관계와 복합 역할의 상세 집계·표시 |
| 설정 출처 | 시작·끝 순번과 목표값·상하한, 개별 덮어쓰기, 적용 전 미리보기 | 보간식·정수 환산·일괄 적용의 세부 동작 |

공통 틀을 사용하더라도 모든 요소를 같은 수식으로 계산하지 않습니다. 연쇄의 선행 깊이와 압박 구간의 반복 횟수는 다르고, 영역 수와 영역 개방량도 다릅니다. 발생 확률은 간격 보장을 뜻하지 않습니다. 목표와 단위를 확정하기 전에는 충족 여부를 임의 계산하지 않습니다.

## 4. 작업과 조건을 합친 화면 — 사용자 피드백 반영

사용자는 v0.7의 작업과 맵 조건을 한 화면에서 보기를 요청했습니다. 상세 입력이 공간을 많이 차지하더라도 핵심 세 조건은 작업 중 조회 가능해야 하며, 설정·변경은 별도 창이나 팝업으로 분리해도 됩니다. 이를 v0.8에 반영합니다.

1. **작업 + 조건 요약:** 중앙 보드 옆에 풀이 가능 수·연쇄·영역 개방의 현재 값, 목표, 빈도·커버리지를 계속 표시합니다. 값이 미설정이거나 결과가 미검증이면 그대로 표시합니다. 후보 저장·이력·비교·복제·부분 생성은 유지합니다.
2. **상세 설정 팝업:** 작업 화면의 ‘상세 설정’에서 요소별 상세 입력으로 진입합니다. 개수·점유율·생성 영역 같은 이번 생성의 입력과는 구분합니다.
3. **분석:** 주요 관문·영역 개방 전후를 확인합니다. 매 스텝 목록은 기본 화면에서 접습니다. 스테이지 목록은 분석 중에도 유지합니다.

왼쪽에는 스테이지 1~N의 목록·순번·안정적인 ID를 표시하고, 검색·추가·복제·순서 변경의 진입점을 둡니다. 순번 변경 시 ID는 보존하는 안입니다. 미저장 상태에서 스테이지를 바꾸는 처리, 실제 순서 변경·게임 반영 계약은 아직 정하지 않았습니다. 목록의 실제 표시 수·너비·스크롤은 이후 조정할 수 있습니다.

화면 검토: [v0.8 작업+조건 목업 열기](wireframes/11-workspace-v08.html), [작업 화면 PNG](wireframes/11-workspace-v08.png), [설정 팝업 PNG](wireframes/13-profile-dialog-v08.png). 화면 전환과 팝업 열기·닫기만 동작합니다. 목록의 맵 선택·순서 변경·편집·저장·생성은 정적 예시입니다. 자동 조정 공식, 세부 단위, 필수/권장 조건과 우회 경로 조사 범위도 계속 논의합니다.

예시 요약의 ‘선행 제거 2개’는 관문 G를 제거하기 전에 필요한 Z·H를 뜻합니다. 전체 맵의 최장 연쇄 깊이나 반복 횟수로 표시하지 않습니다. 영역 개방도 현재 R2의 제거 가능 수와 검증 경로에서 G 제거 후의 수를 구분합니다.

이전 [v0.7 세 화면 목업](wireframes/08-difficulty-v07.html)은 검토 이력으로 보존하며, 별도 맵 조건 화면보다 보드와 요약을 함께 보는 최신 요청을 우선합니다.

## 5. 검증한 작은 예시와 한계

[예시 맵](wireframes/examples/role_chain.json)을 실제 공용 Godot 코어로 검사했습니다. 합법적인 제거 순서는 `Z → H → G → A → B → C`입니다. `Z → H → G`는 관문까지의 선행 관계이며, G를 제거하면 R2의 제거 가능 수가 0개에서 3개가 됩니다.

| 시점 | 전체 남은 수 | 전체 제거 가능 수 | R2 남은 수 | R2 제거 가능 수 | R2 막힘 비율 |
|---|---:|---:|---:|---:|---:|
| 시작 | 6 | 1 | 3 | 0 | 100% |
| Z 제거 후 | 5 | 1 | 3 | 0 | 100% |
| H 제거 후, 관문 직전 | 4 | 1 | 3 | 0 | 100% |
| G 제거 후 | 3 | 3 | 3 | 3 | 0% |

비율의 분모는 해당 시점·영역의 남은 화살표 수입니다. 0개이면 비율은 해당 없음으로 표시합니다. 예시 영역의 화살표는 머리가 해당 영역 안에 있습니다. 일반 맵의 경계·중복 영역 집계 정책은 아직 확정하지 않았습니다.

재검증 명령:

```bash
godot --headless --log-file /tmp/pickup-arrow-role-demo.log --path . \
  --script docs/wireframes/examples/verify_role_chain.gd
```

[분석 기록 JSON](wireframes/examples/role_chain_trace.json)은 이 검증 결과입니다. 목업의 보드 수치는 이 예시에 근거하지만, 후보명·버전·입력 칸은 화면 설명용입니다. 이 예시는 관문 하나를 검증하며 반복 압박의 발생 빈도, 자동 생성, 스테이지별 자동 조정, 모든 풀이 순서의 통계를 검증하지 않습니다. 역순 구성 후 정방향 검증은 생성 방식의 제안이며 구현 완료가 아닙니다.
