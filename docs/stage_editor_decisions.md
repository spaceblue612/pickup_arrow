# 2단계 — 남은 결정과 권장안

상태: 사용자는 남은 권장안을 초기 구현 기준으로 채택했으며, 모호한 내용은 후속으로 두고 확실한 기능부터 구현하도록 요청했습니다. 실제 목표값·상세 판정식·예외 처리까지 모두 확정한 것은 아닙니다. 구현/미구현은 [첫 실제 구현 기록](stage_editor_first_build.md)을 따릅니다.

Discord v0.10 외관, 보드와 세 조건의 동시 조회, 같은 후보의 버전 누적과 명시적 새 후보 분기는 이미 확인한 기준입니다. 이를 다시 선택하도록 요구하지 않습니다. 이 문서는 구현 전에 남은 의미·조작·운영 기준을 정리합니다. 실제 목표 수치는 여기서 고정하지 않습니다.

## A. 맵 조건의 의미

사용자가 ‘토론한 대로 잘 정리되었다’고 확인한 핵심 정의입니다. 구체적인 기본 수치, 자동 조정의 보간식, 복합 사건의 판정·표본 경로 전략까지 모두 확정했다는 뜻은 아닙니다. 아래 추가 설명의 세부 구현안은 이 기준 안에서 명세화하고 결과에 영향을 주는 선택은 확인합니다.

| 번호 | 지정할 사항 | 권장안 |
|---|---|---|
| A1 | 풀이 가능 수 | 해당 시점의 남은 화살 중 바로 제거 가능한 수. 기본은 개수 범위, 비율도 지원하며 분모는 해당 시점·범위의 남은 수. 전체 맵과 선택 영역을 구분하고 판정 자체는 전체 보드로 수행. |
| A2 | 연쇄 단계·커플링 깊이 | 선행 관계가 가장 길게 이어지는 연결 횟수를 깊이로 사용. 특정 화살을 위해 먼저 제거해야 하는 전체 화살 수는 중복을 제외한 별도 지표. 압박 구간의 반복 횟수와도 구분. |
| A3 | 압박 구간·재등장 | 제작자가 선택한 ‘제거 가능 수가 목표 이하’, ‘다음 영역 관문 도달’ 등의 조건으로 구간·사건을 정의. 연속 충족은 한 구간으로, 해소 후 재진입은 새 구간으로 집계. 저선택지 구간과 관문 사건은 별도 유형으로 기록. |
| A4 | 영역 개방 정도 | 해당 영역에서 현재 제거 가능한 수·막힘 비율과, 관문 제거 직후 새로 제거 가능해진 수·비율을 함께 측정. 영역이 열렸다는 이유로 소속 화살을 자동 제거하지 않음. |
| A5 | 빈도·적용 진행 구간 | 기본 간격은 ‘제거한 화살 수 ÷ 최초 전체 화살 수’에 따른 진행률 차이(%p). 사건 시작→다음 시작의 간격을 사용하고, 적용할 진행 구간을 지정. 발생 확률·간격 허용 오차는 별도 선택 옵션. |
| A6 | 커버리지 | 기본은 역할·관문에 실제로 의존하는 대상 화살 수 또는 비율. 분모는 원본 맵 또는 지정 영역의 소속 화살 수이며, 여러 역할·관문의 공통 대상은 중복 제외. 압박이 지속되는 길이는 별도 ‘지속 구간’으로 관리. |
| A7 | 관리 영역·소속 | 저장하는 관리 영역끼리는 겹침을 허용하지 않고 미지정 공간은 허용. 화살의 소속은 머리 위치, 점유율은 영역 안 몸체 칸으로 집계. 영역 생성은 새 화살 전체가 영역 안에 들어가게 제한. |
| A8 | 스테이지별 자동 조정 | 시작·끝 순번과 각 지표의 시작값·끝값·상하한으로 점진적으로 조정하고, 스테이지별 덮어쓰기 지원. 일괄 적용 전 미리보기. 순번 변경만으로 기존 저장 조건을 몰래 재계산하지 않음. |
| A9 | 검증할 풀이 경로 | 기준 경로와 서로 다른 선택 전략·seed의 대안 경로를 재현 가능하게 검사. 원본 관계와 각 경로의 압박·개방 결과를 따로 보존. 검사한 경로에서의 결과를 모든 풀이 순서의 보장으로 표시하지 않음. |

### A2의 구체적 예

`A → B → G`이면 G까지 선행 연결은 2회이고 필요한 선행 화살은 A·B 두 개입니다. 반면 A와 B가 독립적으로 G를 막는다면 가장 긴 연결은 1회지만 선행 제거는 두 개입니다. 이 둘을 같은 ‘연쇄 2단계’로 표시하지 않습니다.

현행 `DependencyAnalyzer.dependency_depth`는 시작 화살을 1로 세는 값입니다. 위 제안의 연결 횟수와 기준이 다르므로 기존 설정을 그대로 새 이름에 매핑하지 않습니다. 표시 이름·변환·저장 버전을 구현 계약에 명시합니다.

### A3~A6의 집계 기준

- 저선택지 압박은 제거 가능 수가 지정 상한 이하로 내려간 상태가 연속되는 구간으로 우선 정의합니다. 같은 상태를 매 스텝 별도 발생으로 세지 않습니다. 지역별 0개는 관문 대기로 정상일 수 있지만, 클리어 전 전체 맵의 0개는 단순 압박 성공이 아니라 진행 불가입니다.
- 저선택지 상태만으로 연쇄가 있다고 간주하지 않습니다. 실제 선행 관계·선행 제거에 의해 새로 열린 화살을 함께 확인합니다.
- 관문 도달·영역 개방은 별도 사건입니다. 여러 조건을 하나의 반복 목표로 묶을 때 AND/OR를 명시하고, 같은 전환을 중복 집계하지 않도록 사건 ID와 근거를 보존하는 안입니다.
- 마지막 한두 개만 남아 선택지가 줄어드는 현상을 의도한 압박으로 자동 인정하지 않습니다. 적용 진행 구간과 최소 잔여 수를 설정할 수 있게 하고, 현재 구간에서 조건 달성이 가능한지 검사합니다.
- 현재 제거 가능 비율·영역 막힘 비율의 분모는 ‘그 시점의 남은 수’, 커버리지의 분모는 ‘원본 적용 대상 수’입니다. 이름과 분모를 함께 표시하며 대상 수가 0이면 해당 없음입니다.
- 특정 관문이 간접적으로 막는 대상은 전체 선행 관계에서 집계합니다. 그 관문을 제거하면 즉시 열리는 수는 다른 방해물까지 해소됐는지 확인한 전후 차이입니다. 커버리지가 크다고 즉시 개방량도 크다고 표시하지 않습니다.
- 압박 구간의 지속 길이는 구간 진입부터 이탈까지의 제거 횟수 또는 진행률 차이로 따로 표시합니다. 간격·지속 길이·대상 커버리지를 같은 퍼센트로 혼용하지 않습니다.
- 매 스텝은 내부 분석 근거로 계산할 수 있지만 화면은 압박 진입·해소·관문·영역 개방 같은 주요 전환점을 기본으로 표시합니다.

관리 영역과 다르게 일시적인 생성 선택 범위·분석 선택 범위는 기존 영역과 겹칠 수 있습니다. 새 역할·요소도 목표·빈도·커버리지·적용 구간·검증 근거라는 공통 구조를 쓰되 지표의 수식은 별도로 정의합니다.

## B. 보드 편집과 생성 조작

B1 확인 기록: 사용자는 머리 칸을 먼저 지정하고 몸체를 이어 그린 뒤, 완성 후 점과 방향을 수정하는 제안에 동의했습니다. 몸체부터 그려 마지막 지점을 화살촉으로 만드는 방식은 기본 조작으로 채택하지 않습니다. 이 확인은 B2~B5나 실제 앱 구현 착수의 승인을 의미하지 않습니다.

| 번호 | 지정할 사항 | 권장안 |
|---|---|---|
| B1 | 화살표 만들기·수정 | 머리부터 몸체를 격자에 그리며 첫 몸체 칸으로 방향 결정. 선택 후 머리·몸체 점을 수정하고, 속성에서 방향 변경과 역할·대상 영역 지정. 겹침·범위·머리 방향 오류는 위치를 표시. 역할 지정만으로 배치 효과를 충족했다고 처리하지 않음. |
| B2 | 영역 만들기·수정 | 사각 선택을 기본으로 하고 칸을 추가·제외해 모양을 다듬음. ‘이번 생성의 선택 범위’와 이름을 붙여 보존하는 ‘관리 영역’을 구분. 경계 변경 시 소속·집계와 연결 분석 갱신. |
| B3 | 부분 생성 입력 | 기본 화면에는 영역·추가 개수 또는 최종 점유율·길이/굴곡·기존 배치 보존을 표시. 기본/보충 화살을 합친 실제 추가 수로 종료. 점유율의 목표 칸 수는 올림하고 실제 칸·비율도 표시. 추가 예정분 미리보기 후 적용. |
| B4 | 목표 미달·중단 | 규칙·영역·기존 배치 보존은 필수. 제작 목표는 필수/권장을 명시. 미달과 계산 중단을 구분하며 자동 완화·덮어쓰기 금지. 규칙상 유효하고 클리어 가능한 미달 결과만 명시적으로 초안에 적용할 수 있게 함. |
| B5 | 작업 보존 | 편집·생성 적용에 실행 취소/다시 실행 제공. 임시 자동 복구본은 후보 버전과 별도로 보존. 미저장 상태에서 스테이지 이동·앱 종료 시 저장/버리기/취소를 선택. 이력 복원은 과거를 덮지 않고 새 저장 버전으로 남김. |

기존 화살표의 위치·방향·몸체를 목표 달성을 위해 자동 변경하지 않습니다. 빈 보드나 수정이 필요한 중간 보드도 구조상 안전한 초안으로 저장할 수 있게 하되, 게임용 유효성·클리어 가능성과 혼동하지 않습니다. 삭제된 역할 화살을 참조하는 조건은 조용히 다른 화살에 연결하지 않고 수정 필요로 표시합니다.

한 화살표의 몸체는 현재 규칙의 연결·머리 방향 기준을 유지합니다. 방향 변경으로 자기 몸에 막히는 경우 등은 오류·풀이 경고로 표시하며 임의로 다른 게임 규칙을 도입하지 않습니다. 생성의 ‘연결’은 화살표 몸체를 합치거나 겹치는 뜻이 아닙니다.

탐색에는 시간·시도 상한과 취소를 제공합니다. 구체적인 기본 상한은 실제 대형 맵 성능 측정 후 정하고 사용자가 늘릴 수 있게 합니다. 대기 중인 결과가 현재 편집본보다 오래된 경우 자동 적용하지 않습니다.

## C. 확정·스테이지 관리·게임 반영

| 번호 | 지정할 사항 | 권장안 |
|---|---|---|
| C1 | 확정안과 게임 반영 | 스테이지마다 후보의 특정 저장 버전 하나를 확정안으로 지정. 규칙·클리어 가능성·명시한 필수 조건을 확인한 뒤 별도 ‘게임 반영’으로 내보냄. 이후 후보를 수정해도 이미 반영한 버전은 바뀌지 않음. |
| C2 | 스테이지 추가·복제·순서 | 안정적인 ID와 플레이 순서를 분리. 복제는 새 ID, 정렬은 순번만 변경. 삭제는 우선 보관 처리하고 관련 후보·이력은 유지. 순서 변경도 미리보기 후 게임 반영하며 기존 진행 데이터와의 호환성 검사. |
| C3 | 고정 맵·기존 무작위 모드 | 새 제작 흐름은 도구에서 확정한 배치를 게임이 그대로 로딩. 무작위 생성은 제작 도구에서 반복 사용. 기존 런타임 random 모드는 이행 동안 유지하고 제거·전환은 별도 승인. |
| C4 | 기존 데이터 이행·복원 | 기존 스테이지 ID·순서·생성 설정을 보존해 가져오기. 원본을 지우거나 변환 결과로 덮지 않고 비교·검증 후 전환. 후보의 과거 저장 버전은 자동 삭제하지 않으며 게임 반영 전 상태로 복원할 수 있게 함. |

풀이 경로 의존적인 필수 조건은 A9에서 합의한 검사 경로·방법에 대한 충족 여부로 기록합니다. 일부 경로의 통과를 모든 경로 보장으로 바꾸지 않습니다. 강한 압박이 어떤 경로에서도 유지되어야 하는 조건을 지정하면 그 보장에 필요한 추가 검증 범위를 먼저 합의해야 합니다.

후보 저장은 게임 반영과 다릅니다. 미완성·목표 미달 초안의 저장을 허용하더라도 정식 반영에서는 필요한 검사를 통과해야 합니다. 필수 검사 실패를 경고 무시로 통과시키지 않으며, 권장 목표만 미달했을 때에는 미달 내용을 확인하고 반영할 수 있게 하는 안입니다.

## D. 사용자가 직접 결정하지 않아도 되는 기술 설계

파일 경로·JSON 필드명·프로세스 호출·IPC·안전한 파일 교체·분석 캐시·모듈 구성은 위 제작 기준에 맞춰 구현자가 설계합니다. 호환성 파괴·데이터 삭제·운영 방식 변경이나 검증 의미 변경이 필요하면 별도 확인합니다.

기존 생성 회귀 실패 2개는 구현 4단계에서 원인을 해결합니다. 테스트 기대를 바꿔야 하면 이유와 영향을 제시하고 확인받으며, 단순히 통과를 위해 기준을 낮추지 않습니다. 제작 도구의 충분한 탐색 시간과 기존 런타임 생성의 성능 기준은 별도 계약으로 다룹니다.

검토 순서는 A → B → C입니다. A의 핵심 방향은 확인했으며 다음은 B의 편집·생성 조작입니다. 수치의 의미를 기준으로 생성 조건·분석 결과·저장 계약을 맞춥니다. A의 확인은 2단계 전체 완료나 실제 앱 구현 착수를 의미하지 않습니다.
