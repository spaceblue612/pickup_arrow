# 편집기 기본 개선과 직접 조작 — 2026-10-20

사용자 요청은 글자 가독성·같은 스테이지 재선택·화살의 성립 조건·좌표 대신 보드 직접 조작입니다. 기본 마우스 조작과 그룹 회전·꺾임 간격·머리/꼬리 연장까지 구현했습니다.

## 반영한 기능

- 우측 상단 **에디터 환경설정 → 기준 글자 크기**에서 `−1px`·`+1px`로 1px씩 조정하고 `기본값`으로 되돌립니다. 본문 기준 최소 13px·기본 15px·최대 19px이며 경계에서는 해당 버튼을 비활성화합니다. 제목·작은 설명의 상대적인 크기 차이는 유지합니다. 즉시 미리 보고 환경설정 저장 후 재실행해도 유지됩니다. 저장 없이 닫으면 저장된 설정으로 돌아갑니다. 보드 좌표·셀 크기·창 확대율은 바꾸지 않습니다. ‘이전보다’ 같은 변경 설명은 옵션에서 제거했습니다.
- 글자 크기는 `authoring/settings.json`의 `textSizeOffset`이며 스테이지·후보의 데이터가 아닙니다. 내부 값은 CSS 기준 13px에 대한 차이이며, 기존에 저장한 0~4도 그대로 읽습니다. 필드가 없으면 기본 15px입니다. 범위·기본값은 공통 `tool/src/text-size.mjs`에서 관리합니다. 저장에 실패하면 실행 중 설정도 교체하지 않습니다.
- 현재 스테이지를 다시 선택하면 아무 전환도 하지 않습니다. 작업 후보·선택·분석·미저장 상태·실행 취소 이력을 유지하고 경고 창을 열지 않습니다. 다른 스테이지로 이동할 때의 미저장 보호는 유지합니다.
- 화살표를 한 칸만 클릭하고 놓으면 배치를 만들지 않으며, 미저장 상태·이력도 추가하지 않습니다. 최소 두 칸을 그려야 화살표가 됩니다. 그리는 중 첫 칸은 원형 시작 표시이며 확정 화살표가 아닙니다.
- 머리는 첫 번째 칸, 진행 방향은 첫 번째와 두 번째 칸의 상대 위치로 결정합니다. 방향 선택 상자와 몸체 좌표 직접 수정은 제거했습니다. 방향은 읽기 전용입니다. 파일의 `direction` 필드는 기존 게임 호환을 위해 유지하지만 신규 그리기에서 몸체와 별개로 지정하지 않습니다.

## 전체 이동

**기본 조작**에서 화살표의 직선 몸통을 좌측 드래그합니다. 머리·꼬리는 자동 연장·축소, 꺾인 코너는 양쪽 간격 조절입니다. 직선 몸통이 없거나 끝점·코너를 잡고 전체 이동하려면 우클릭 → **전체 이동**을 선택합니다. 이동 중 분홍 미리보기를 표시하며 놓을 때 검사합니다. 회전·길이 변경 없이 머리와 모든 몸체 칸을 같은 이동량으로 옮깁니다.

실제 판단은 새 `translate_arrow` 요청으로 Godot의 공통 `StageValidator`를 호출합니다. TypeScript에 충돌 규칙을 별도로 구현하지 않습니다. 이동 시작부터 도착까지 한 칸씩 직각으로 이동해 겹침·금지 칸·보드 이탈을 검사하므로, 도착점만 비어 있다고 다른 화살을 통과할 수 없습니다. 둘 이상의 축으로 움직이면 남은 거리가 큰 축을 먼저 검사하고 동률이면 가로를 우선합니다. 장애물을 돌아가는 경로를 자동으로 찾지는 않습니다. 필요하면 여러 번의 이동으로 나누어 배치합니다.

한 번이라도 실패하면 전체 이동을 취소하고 원래 화살을 보존합니다. 성공한 전체 이동 하나는 실행 취소/재실행 하나입니다. 기존 역할·영역 데이터·후보·과거 버전은 자동 변경하지 않습니다. 머리 위치가 바뀌어 영역 소속은 새 위치로 조회하며 이전 분석은 무효화됩니다. 단순한 인접은 기존 규칙대로 허용하고 다른 화살과 같은 칸을 점유하는 겹침은 거절합니다.

## 기존 자료의 1칸 화살

기존 게임·분석 예제·저장 버전에는 1칸 화살이 있습니다. 이를 일괄 확장하면 주변 배치·의존 관계가 달라지므로 자동 수정하지 않습니다. 편집기는 목록과 경고를 표시하고, 해당 화살을 삭제 후 2칸 이상으로 다시 그리도록 안내합니다. 잘못된 중간 초안과 과거 이력을 보존하는 저장 정책은 유지합니다.

공용 코어는 `stage_contract=authoring_v1`에서 최소 2칸을 검사합니다. 편집기의 검증·분석·재생·이동·내보내기는 main 프로세스에서 이 계약을 강제합니다. 기존 게임과 기존 CLI 요청은 기본 `runtime_v1` 호환을 유지합니다. 따라서 신규 제작 기준을 적용했다고 기존 게임 스테이지나 이력을 몰래 바꾸지 않습니다. 편집기의 `검증 예제로 시작`은 모든 화살이 2칸 이상인 별도 [예제](../tool/examples/role_chain.json)를 사용하며, 기존 검증용 예제는 보존합니다.

## 구현한 기본 조작 원칙

사용자가 승인한 공통 원칙이며 보드 이동 키는 Space 대신 **Shift**입니다.

| 기본 조작 | 동작 |
|---|---|
| 화살 좌클릭 | 화살 전체 선택 |
| 머리·꼬리 좌측 드래그 | 바깥으로 연장, 기존 몸체를 따라 안쪽으로 축소. 최소 2칸 |
| 직선 몸통 좌측 드래그 | 화살 전체 이동 |
| 꺾인 코너 좌측 드래그 | 양쪽 간격 조절 |
| 빈 칸 좌클릭 | 선택 해제 |
| 빈 칸 좌측 드래그 | 시작 칸이 머리인 새 화살 생성, 최소 2칸 |
| 우클릭 | 클릭한 대상에 맞는 기능 메뉴 |
| Shift+좌측 드래그 | 화살·빈 칸에 관계없이 보드 이동 |
| 마우스 휠 | 포인터 위치를 중심으로 확대·축소 |

Shift 보드 이동은 화살 선택·생성·변형보다 우선하며 화살 배치나 후보 이력을 바꾸지 않습니다. 우클릭은 기능 메뉴로 유지하고 보드 이동에 중복 배정하지 않습니다. 기본 조작에서 Shift를 다중 선택에 겸용하지 않습니다.

기본 조작에서 마우스를 올리면 머리·꼬리·직선 몸통·꺾인 코너를 구분해 해당 칸을 강조하고, 보드 왼쪽 위에 드래그 시 실행할 기능을 안내합니다. 빈 칸이나 보드 밖으로 나가면 안내를 숨깁니다. 클릭만 하면 선택하며 5px 이상 드래그할 때 변형을 시작합니다. 메뉴에서 명시한 도구와 영역·금지 칸 도구는 자동 분류보다 우선하고, Shift+좌측 드래그는 여전히 보드 이동입니다.

클릭과 드래그는 화면 기준 5px 문턱으로 구분합니다. 누를 때 정한 동작은 드래그 중 Shift를 누르거나 떼어도 바뀌지 않습니다. 우클릭한 몸체 기준점을 표시하고, 기능을 고르면 바뀔 부분을 금색으로 강조한 뒤 분홍 미리보기 → 놓을 때 검사·확정으로 통일합니다. 영역·금지 칸 전용 도구는 해당 도구가 활성화된 동안 우선하고, Shift 보드 이동은 전용 도구 중에도 우선합니다. 확대 범위는 25~600%이며 ‘화면 맞춤’으로 돌아옵니다.

## 우클릭 변형 도구

| 기능 | 동작 |
|---|---|
| 전체 이동 | 두 칸 화살도 머리·꼬리 어느 곳에서든 전체 이동. 메뉴로 명시한 동작은 자동 연장보다 우선 |
| 전체 90° 회전 | 머리를 고정하고 드래그 방향에 따라 좌우 90° 회전 |
| 머리/꼬리 쪽 꺾임 추가 | 우클릭한 칸을 고정하고 선택한 쪽 그룹만 좌우 90° 회전 |
| 꺾임 간격 조절 | 실제 꺾인 칸을 좌우·위아래로 드래그해 양쪽 직선 구간 길이를 조절. 대각선 드래그는 두 간격을 동시에 변경하며 양쪽 연결 길이는 각각 최소 1격자 |
| 머리/꼬리 연장·축소 | 표시된 끝점을 잡고 이어서 드래그. 바깥으로 직각 연장하거나 기존 몸체를 따라 꺾임까지 축소 |

머리 방향은 항상 처음 두 칸으로 다시 정합니다. 놓을 때 `reshape_arrow`로 Godot의 공통 검증기를 실행하며 사선·겹침·자기 겹침·금지 칸·경계 이탈은 적용하지 않습니다. 변형은 최종 배치 검사이며 회전 중간의 원호까지 검사하는 물리 이동은 아닙니다. 성공한 편집 하나는 실행 취소/재실행 하나입니다. 자동 풀이 분석은 드래그마다 실행하지 않고 기존 분석을 무효화합니다.

끝점 축소는 잡은 머리·꼬리를 기존 몸체의 바로 다음 칸으로 끌면 그 끝칸을 제거하는 방식입니다. 꺾인 구간도 몸체를 따라 줄일 수 있고, 전체 두 칸이 남으면 멈춥니다. 한 칸 화살이나 불연속 연결은 만들지 않습니다. 같은 드래그에서 경로를 되짚으면 줄였던 부분을 복원하며, 줄인 지점에서 새 방향으로 이어 그릴 수도 있습니다. 머리 쪽을 줄이면 남은 첫 두 칸으로 머리 위치·방향을 다시 정하고, 꼬리만 줄이면 기존 머리를 유지합니다. 확정 하나는 실행 취소 하나이며 최소 길이에서 더 줄이려는 입력만으로 새 이력을 만들지 않습니다.

[머리 축소 미리보기](design/arrow-editor-endpoint-shortening.png). 실제 Electron 입력으로 머리·꼬리의 꺾임 통과 축소, 최소 두 칸과 추가 이력 방지, 같은 드래그에서 복원·새 방향 연장, 실행 취소/재실행·Esc 취소를 통과했습니다. 기존 연장·코너 간격 조절·머리 통과 반전·후보 저장·재생 회귀도 함께 통과했습니다.

간격 조절은 머리를 고정하지 않습니다. 선택점 앞뒤의 가장 가까운 꺾임점 또는 끝점까지를 조절 구간으로 잡고, 그 바깥의 머리 쪽·꼬리 쪽 그룹은 각각 연결 구간에 수직인 방향으로 평행 이동합니다. 따라서 ‘아래로 내려오다 오른쪽으로 꺾이는 점’은 좌우 드래그 시 머리 쪽 그룹이 좌우로, 위아래 드래그 시 꼬리 쪽 그룹이 위아래로 따라옵니다. 그룹 내부 모양과 직각 연결은 유지하고 양쪽 길이는 독립적으로 최소 1격자에서 멈춥니다. 미리보기에는 양쪽 그룹을 모두 강조하며 하나의 편집으로 확정·취소합니다.

머리와 직접 연결된 구간은 코너를 머리 너머로 끌면 반대편으로 이어집니다. 정확히 머리와 겹치는 칸에서는 0길이가 되지 않도록 기존 쪽 한 격자를 유지하고, 그보다 더 진행하면 반대쪽에 직선 구간을 다시 구성합니다. 머리 방향은 새 첫 두 칸에서 자동으로 반전되며 별도 방향 편집은 하지 않습니다. 다른 코너를 통과시키거나 꼬리 쪽 간격을 뒤집는 동작은 추가하지 않았으며 해당 구간은 최소 한 격자를 유지합니다. 반전 결과도 동일한 Godot 충돌·금지 칸·경계 검증을 통과해야 합니다.

실제 입력 검증: 수평·수직·대각선 드래그, 최소 길이, 한 번의 실행 취소로 양쪽 복원, Esc 취소를 통과했습니다. [양쪽 간격 조절 미리보기](design/arrow-editor-bend-spacing.png)에서 금색은 기존 양쪽 구간, 분홍색은 적용 예정 모양입니다.

2026-10-21 추가 검증: [마우스 위치별 안내](design/arrow-editor-hover.png), [코너 좌클릭 드래그](design/arrow-editor-corner-drag.png), [머리 통과 후 방향 반전](design/arrow-editor-head-crossing.png)을 실제 입력으로 확인했습니다. 클릭만 할 때 선택·미저장 상태 보존, 코너에서 Shift 보드 이동, 드래그 중 Shift 변경 시 동작 유지, 머리 반전 후 실행 취소/재실행·Esc 취소도 통과했습니다. 우클릭 드래그는 제공하지 않습니다.

간격 조절 중 이동했다가 원래 위치로 돌아와 놓으면 변경 없이 조작을 종료하고 기본 조작으로 복귀합니다. 코너 직접 드래그와 메뉴로 선택한 간격 조절 모두 동일하며, 이 경우 코어 요청·미저장 상태·실행 취소 이력을 추가하지 않습니다.

첫 수정 시 안내 문구가 처음 생기면서 보드 영역이 줄어드는 현상은 상단 일반 안내 영역을 항상 같은 높이로 유지해 방지합니다. 앱을 다시 열면 기본 안내를 표시하고, 긴 문구는 한 줄 말줄임과 전체 내용 툴팁을 제공합니다. 안내가 생기거나 바뀌는 것만으로 보드 배율·위치·크기가 달라지지 않습니다. 오류 경고는 별도 표시를 유지합니다.

## Esc 취소

현재 상황에 맞춰 메뉴 닫기, 변형 대기·미리보기 취소, 전용 도구 종료, 보드 이동 원복, 열린 창 닫기를 수행합니다. 검사 중 취소하면 코어 요청을 중단하고 늦게 도착한 결과도 적용하지 않습니다. 확정된 과거 편집은 Esc가 아니라 실행 취소로 되돌립니다. 복구 창을 Esc로 닫으면 복구본을 보존한 채 편집을 잠그고 ‘복구 창 열기’를 제공하며, 명시적으로 복구/버리기를 선택하기 전에는 덮어쓰지 않습니다.

## 후속으로 남긴 직접 편집

코어를 상시 실행하는 성능 개선은 사용자가 현재 반응 속도로 작업 가능하다고 판단하여 보류했습니다. 기능이 더 붙고 지연이 실제 작업에 부담될 때 다시 검토하며, 현재 요청마다 헤드리스 Godot를 호출하는 방식은 유지합니다.

임의의 몸체점을 자유롭게 옮기고 고정 그룹과 최단 직각 경로로 자동 재연결하는 일반 부분 이동은 아직 구현하지 않았습니다. 동률 연결 경로·그룹 경계 등은 후속으로 남깁니다. 이번 세 가지 변형과 구분합니다.

| 기능 | 유지할 의도 | 먼저 정할 부분 |
|---|---|---|
| 부분 이동 | 몸체점을 선택하고 앞 또는 뒤를 그룹 이동, 고정 부분과 최단 직각 경로로 재연결 | 머리 쪽/꼬리 쪽 선택 표시, 같은 길이의 연결 후보 선택, 연결 불가 시 취소 기준 |

공통 기준은 사선 금지, 머리 방향 자동 결정, 바뀔 그룹·연결 경로의 미리보기, 실패 시 원본 보존입니다. 후속 기능이 나올 때까지 임의의 좌표·방향 직접 입력은 다시 열지 않습니다.

## 검증

- TypeScript 검사·Vite 빌드 통과.
- Node 테스트 28개: 기존 저장·코어 연결·설정·제작 계약과 함께 실제 이동/변형, 양축 간격 조절의 8방향 배치·머리 반전·충돌 거절, 머리/꼬리 축소·최소 2칸·되짚기 복원·줄인 지점에서 연장·남은 몸체에 따른 방향 갱신을 검사합니다.
- Godot 10개 스위트: 필수 게임플레이 4개, bridge/CLI, validator, 분석, `test_editor_manipulation.gd`, `test_arrow_reshape.gd`를 통과했습니다. 최소 2칸·방향 일치·사선 거부·이동·변형·경로 충돌·금지 칸·경계·원본 불변성을 검사합니다.
- 샌드박스를 유지한 실제 Electron 입력: 글자 크기·동일 스테이지 선택·최소 2칸·전체 이동과 함께 우클릭 메뉴, Shift 보드 이동, 드래그 시작 동작 유지, 전체/그룹 회전, 꺾임 간격 최소 길이, 머리/꼬리 직각 연장, 포인터 중심 확대, 드래그/검사 중 Esc, 복구 창 Esc 후 파일 보존을 통과했습니다. 후보 분기·영역 선택·재생 회귀와 네 가지 창 크기 검사도 유지합니다.
